# 수신함 정리 (`sort`)

위원회 수신함(`_수신함`)에 쌓인 자료를 **파일 내용까지 읽고** 알맞은 회의 폴더로 옮긴다.
사람이 "이건 9/17 공청회 자료네" 하고 나누던 일을 클로드가 대신한다.

- 사무실: 국회(`/assembly`) · 부서 `review`(자료실 정리팀) · 직원 `plan`(자료 분류) `move`(폴더 정리)
- 실행: GitHub 서버, `.github/workflows/sort.yml` — **예약 없음**. 상임위 메일(`mail`)이 드라이브에
  새 자료를 저장한 실행에서 이어서 돌리고, 사이트 ▶ 시작으로도 돌린다.
- 개인 메모: `ai-assembly/05_수신함정리/README.md`

## 어떻게 도는가

1. 위원회마다 `_수신함`의 파일 목록과 위원회 폴더 목록(회의 폴더들)을 읽는다.
2. 파일에서 앞부분 글자를 뽑는다 — 한글(.hwp/.hwpx)·PDF·텍스트. 실패하면 이름만으로 판단한다.
   - `.hwp`(한글 5.0)는 OLE 복합문서라 `BodyText` 스트림을 zlib 로 풀어 글자 레코드만 모은다(`sort_drive._hwp_text`).
3. 클로드에게 "어느 폴더로 옮길지" 묻는다(`sort_plan.SYSTEM`). 답은 파일마다 `{file, folder, reason}`.
4. 답을 검사한다(`clean_plan`) — **여기가 안전장치다**.
   - 수신함에 없는 파일 이름은 버린다(지어낸 이름 방지).
   - `folder` 가 비면 **옮기지 않는다**. 확신 없는 것은 수신함에 그대로 두는 편이 낫다.
   - 기존 폴더가 아니면 새 폴더로 보고, `allow_new_folders: false` 면 거른다. 경로(`/`)는 금지.
5. 옮기고(부모만 바꾼다 — 복사·삭제 아님) 수신함의 `_정리기록.md` 에 내역을 덧붙인다.

**삭제는 어떤 경우에도 하지 않는다.** 잘못 옮겼으면 `_정리기록.md` 를 보고 되돌리면 된다.

## 공개 저장소 주의 (사용자 결정 2026-09-17)

파일 이름·폴더 이름은 의원실 내부 자료다. 커밋되는 상태 파일·실행 일지에는 `"재경위 3건 정리, 1건 보류"`
처럼 **건수만** 남기고, 무엇을 어디로 옮겼는지는 **드라이브의 `_정리기록.md`** 에만 쓴다.

## 설정 (`config.actions.yaml`)

- `rules`: 모든 위원회에 적용할 규칙(일반 규칙보다 우선). 사용자가 "이런 자료는 저기로"라고 정할 때마다
  여기에 한 줄 더한다 — 코드는 고치지 않는다. 예: 국정감사 자료는 `_참고자료` 로(2026-09-17).
  위원회마다 다르게 주려면 `committees[].rules`.
- `committees[]`: `label`(위원회), `inbox_id`(수신함 폴더), `parent_id`(회의 폴더들이 있는 위원회 폴더),
  `allow_new_folders`(새 폴더를 만들어도 되는지).
- `llm_providers`: `[claude_cli, gemini]` — 앞의 것부터. CI 에서는 `CLAUDE_CODE_OAUTH_TOKEN` 을 쓴다.

## 모델이 형식을 어겼을 때 (2026-09-17 실제 사례)

분류는 정확한데 `{"moves": [...]}` 대신 배열만 답한 적이 있다. 그래서
`extract_json`(공통)이 배열도 뽑고, `SCHEMA` 는 객체·배열 둘 다 받고, `clean_plan` 이 양쪽을 처리한다.

## 시험해 보기

```bash
python -m pytest -q automations/sort            # 네트워크 없이 도는 테스트
python automations/sort/run_sort.py --dry-run   # 실제 드라이브를 훑고 계획만 출력 (옮기지 않음)
```

Actions → "수신함 정리" → Run workflow → "시험 실행"을 켜도 같다(옮기지 않고 실행 기록에만 찍힌다).
