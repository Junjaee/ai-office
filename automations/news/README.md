# 기사 수집 (news)

의원·위원회 관련 기사를 구글 뉴스에서 3시간마다 모아, 중복을 합치고 묶음별로 정리해
구글 드라이브에 하루치 문서로 남긴다. 화면(국회 사무실 → 뉴스 모니터링팀) 카드에 결과가 보인다.

## 무엇을 하나

| 직원(작업) | 하는 일 |
|---|---|
| `collect` 기사 모으기 | 설정의 검색어마다 구글 뉴스 RSS 를 조회한다 (키 불필요) |
| `digest` 요약 정리 | 같은 기사를 하나로 합치고, 묶음별로 나눠 하루치 마크다운을 만들어 드라이브에 올린다 |

문장을 새로 쓰는 AI 요약은 별도(유료) 키가 필요해 넣지 않았다. 대신 중복 합치기, 묶음별
나누기, 매체별 건수 세기까지 한다.

## 결과물

`내 드라이브/직장/국회/01. 의정활동/12. 언론모니터링` (폴더가 없으면 자동으로 만든다)

```
12. 언론모니터링/
├── _manifest.json          이미 본 기사 (중복 방지, 기본 60일 보관)
└── 2026/2026-09/2026-09-10.md
```

하루치 문서는 실행할 때마다 그날 기록 전체로 다시 만든다. 그래서 몇 번을 돌려도 같은 결과가 나온다.

## 설정 (`config.actions.yaml`)

| 키 | 뜻 |
|---|---|
| `queries` | 검색어 목록. `group` 은 문서에서 나눠 보일 묶음 이름 |
| `search_days` | 검색어당 최근 며칠 기사를 받아올지 (기본 1일) |
| `manifest_days` | 이미 본 기사 기록을 며칠 보관할지 (기본 60일) |
| `drive_parent_id` | 결과 폴더를 만들 상위 폴더 id (`01. 의정활동`) |
| `drive_folder_name` | 결과 폴더 이름 |

검색어를 바꾸려면 `queries` 만 고치면 된다. 예를 들어 지방의회 기사가 많이 섞이면
`예결위` 를 `국회 예결위` 로 바꾼다.

## 실행

```bash
python automations/news/run_news.py --dry-run   # 저장 없이 기사만 받아 미리보기
python automations/news/run_news.py             # 드라이브 저장 + 상태 파일 기록
```

예약은 GitHub Actions (`.github/workflows/news.yml`) 가 3시간마다 돌린다
(cron `0 */3 * * *` = KST 00·03·06·09·12·15·18·21시). 실행 위치는 GitHub 서버다.

## 비밀값

드라이브 저장용 `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` / `GOOGLE_REFRESH_TOKEN`
(회의록 수집과 같은 값). 뉴스 RSS 는 키가 필요 없다.

## 테스트

```bash
python -m pytest -q automations/news automations/common
```

네트워크 없이 돈다. RSS 파싱은 XML 문자열로, 드라이브 저장은 가짜 저장소로 확인한다.
