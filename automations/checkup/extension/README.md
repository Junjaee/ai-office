# 영유아검진 예약기 (크롬 확장)

하이엔 소아청소년과의원 영유아검진을 **네이버 예약이 열리는 월요일 9시 정각**에,
날짜 고르기부터 **예약 완료까지** 한 번에 잡는다.

## 조사한 것 (2026-11-16)

- 하이엔은 영유아검진을 **네이버 예약**으로만 받는다 (병원 홈페이지 highendped.com 영유아검진 안내).
  예약 화면: `https://booking.naver.com/booking/13/bizes/1432168`
- **매주 월요일 09시에 다음 주 월~금이 열린다.** 당일 예약 불가. 상품 설정에도 여는 시각이 박혀 있다
  (`bookableSettingJson.openDateTime = 2026-11-16T09:00:00+09:00` — 매주 다음 월요일로 바뀐다).
- 상품이 둘이다 — `영유아 검진 (월요일~금요일)`, `영유아 검진 (화요일~토요일)`. 하루 여섯 칸
  (10:30 · 11:30 · 13:30 · 14:30 · 15:30 · 16:30), 한 시간에 한 명.
  11-16(월) 오후에 보니 다음 주 닷새가 **전부 마감**이었다 — 그래서 정각에 잡아야 한다.
- 예약하면 **바로 확정**된다(병원 승인 단계 없음).
- 병원이 건 조건: **본원 진료 기록이 있는 아이만**(초진은 취소됨), 2차(4~6개월) 검진부터,
  **세 번 취소하면 1년 이용 정지**(당일 취소·노쇼 포함).

## 예약까지 눌러야 하는 것 전부

| 단계 | 화면 | 누가 |
|---|---|---|
| 1 | 날짜 (달력) | 확장 — 희망 날짜 순서대로 |
| 2 | 시간 | 확장 — 희망 시간 순서대로 |
| 3 | 필수 선택 `영유아검진(2~8차)` | 확장 (이미 체크돼 있으면 그대로) |
| 4 | **다음단계** | 확장 |
| 5 | 예약자 이름·연락처 | 네이버 회원정보가 저절로 들어간다 (손댈 것 없음) |
| 6 | 요청사항 | 선택 칸 — 비워 둔다 |
| 7 | 추가 정보 여섯 칸 (아래 표) | 확장 |
| 8 | **동의하고 예약하기** | 확장 ([끝까지 자동]이 켜져 있을 때) |

추가 정보 여섯 칸(전부 필수):

| 질문 | 종류 | 넣는 답 |
|---|---|---|
| 본원에 진료 기록이 있습니까?(차트 번호 있음) | 고르기 | 있음 |
| (필수)개인정보 제공 동의 | 고르기 | 동의 |
| 주민등록번호 확인 안내로 연락드립니다 | 고르기 | 동의 |
| 영유아검진 받을 아이 - 이름 / 생일(6자리) | 글칸 | 패널에 적은 값 |
| 엄마 생일(6자리), 아빠 생일(6자리) | 글칸 | 패널에 적은 값 |
| 정보 누락시 취소에 동의 하시나요? | 고르기 | 동의 |

이 여섯 칸은 병원 공통 설정이고, **영유아 검진 두 상품(월~금 `6826611`, 화~토 `6937253`)은 둘 다 이걸 쓴다**
(상품 전용 질문 없음 — 2026-11-22 설정값 재확인). 연습용인 **교정 클리닉은 질문이 다르다** — 상품 전용 넷:
아이 이름/나이(글칸) · 개인정보 제공 동의(`네 확인했습니다.`) · 교정 과목(체크칸) · 당일 취소 확인(`네 확인했습니다.`).
그래서 고르기는 글자를 정해 두지 않고 규칙으로 고른다(`rules.js` `pickOption`): "있음"·"동의" → 보기가 하나면 그것 →
동의·확인하는 뜻의 보기. 뜻 모르는 보기는 누르지 않고 멈춘다. 필수 체크칸은 첫 칸을 고른다.
병원이 질문을 바꿔도 대부분 따라가지만, **새 글칸이 생기면 못 채우고 멈춘다**.

약관 체크칸은 따로 없다 — 마지막 단추 이름이 "동의하고 예약하기"다. 휴대폰 본인인증도 꺼져 있다
(`isPhoneAuthenticationRequired: false`). 단, **네이버 회원정보에 이름·연락처가 비어 있으면** 예약이 막힌다.

## 설치 (한 번만)

1. 크롬 주소창에 `chrome://extensions`
2. 오른쪽 위 **개발자 모드** 켜기
3. **압축해제된 확장 프로그램을 로드합니다** → 이 폴더(`automations/checkup/extension`) 고르기

고친 뒤에는 그 화면에서 **↻**, 그리고 예약 화면 **F5**.

## 쓰는 법 (월요일 아침)

1. 8시 50분쯤 크롬에서 **네이버 로그인**.
2. 예약 화면에서 원하는 검진 상품(월~금 또는 화~토)의 **예약하기**를 눌러 상품 화면을 연다.
3. 오른쪽 아래 패널을 채운다.
   - **시작 시각** — 기본은 빈 칸([시작]을 누른 때부터 돈다 — 자리를 골라 두고 열렸는지 계속 확인한다).
     `09:00:00` 처럼 적으면 네이버 서버 시계로 그 시각까지 아무것도 안 하고 있다가 출발한다.
   - **지켜볼 시간** `30`분 — 이 시간 동안 빈 자리(취소분 포함)를 2초에 한 번 확인한다.
   - **희망 날짜** — 다음 주 월~금이 미리 적혀 있다. 싫은 날은 지우고, 먼저 잡고 싶은 날을 앞에.
   - **희망 시간** — `10:30, 13:30` 처럼 24시간제로, 앞이 먼저. 비우면 빈 칸 아무거나.
   - **아이 이름 / 생일**, **엄마·아빠 생일** — 신청서에 그대로 들어간다.
   - 패널의 모든 칸은 **적는 족족 저장**된다 — [시작]을 안 눌러도, 확장을 ↻ 해도, 크롬을 껐다 켜도 남는다.
     (희망 날짜는 지난 날만 빠지고, 전부 지났으면 다음에 열리는 주로 다시 채워진다.
     확장을 **삭제**했다 다시 올리면 지워진다.)
   - **끝까지 자동** — 켜 두면(기본) 예약 단추까지 누른다. 끄면 신청서만 채우고 멈춘다.
4. **[시작]**. 그 탭을 **앞에 띄워 둔다**(가려진 탭은 크롬이 시계를 늦춘다).

```
끝까지 자동 — 자리를 잡으면 예약 단추까지 누릅니다
출발!
아직 안 열렸어요 — 26. 11. 30.(월) 09:00 예약오픈. 자리를 골라 두고 열릴 때까지 계속 확인합니다
잡았어요 — 2026-11-30 10:30 (1번째 화면)
신청서 6칸 중 6칸 채움
예약 단추를 눌렀어요 — 동의하고 예약하기
성공 — 예약이 접수됐어요. 이 화면과 네이버 알림에서 날짜·시간을 확인하세요
```

희망 날짜·시간을 넓게 적을수록 잘 잡히지만, **적은 것 중 아무거나 잡힌다** — 못 가는 날은 꼭 지울 것
(취소 세 번이면 1년 정지).

## 연습 (예약되지 않는다)

자리가 남은 **`교정 클리닉` 상품 화면**에서 시작 시각을 비우고 [시작].
영유아 검진 상품이 아니면 확장이 **예약 단추를 절대 누르지 않는다** — 신청서가 채워지는 것만 본다.
끝나면 그 화면에서 그냥 뒤로 나오면 된다.

## 하는 일

```
서버 시계로 시작 시각까지 기다림
  → 시간표만 확인한다 (화면이 쓰는 hourlySchedule 요청을 희망 날짜 범위로)
      처음 10초는 초당 4번, 그 뒤로는 2초에 한 번 (간격을 두는 이유는 아래 '막힘')
  → 빈 칸이 보이는 순간 상품 화면을 그 날짜로 다시 연다 (…/items/<상품>?startDate=날짜)
  → 달력 → 시간 → 필수 선택 → 다음단계      (빈 칸 발견부터 여기까지 실측 약 1.3초)
  → 추가 정보 여섯 칸 채움 → 동의하고 예약하기
  → 화면이 "내 예약"(/my/bookings/번호)으로 바뀌면 성공
```

**여는 시각 전에 시작해도 된다**(2026-11-22 실제 화면에서 확인). 열리기 전에도 날짜·시간은 눌리고,
다음 단추만 `26. 11. 23.(월) 09:00 예약오픈` 이라는 글자로 잠겨 있다. 확장은 자리를 골라 둔 채 [시작]을 누른 때부터
서버에 '열렸나'(bizItems 의 `isOpened`)를 **2초에 한 번**, 여는 시각 2초 전부터 10초 뒤까지는 초당 8번 묻고, 열렸다는 답이 오는 즉시
화면을 다시 열어 넘어간다 — 이 PC 시계가 어긋나도 서버의 답을 따른다. 그래서 **시작 시각은 비워 둬도 된다.**

아이사랑 확장처럼 열리기 전부터 계속 쏘지 않는 이유: 아이사랑은 예약 단추가 눌리고 서버가 "아직"이라고
답해 주지만, 네이버는 열리기 전에 **다음 단추 자체가 잠겨** 신청서로 갈 수 없다(보낼 것이 없다).
그리고 네이버는 많이 물으면 막는다(아래).

## 막힘 (2026-11-22 실측)

쉬지 않고 묻게 해 봤더니(초당 25번) **8초쯤 만에 네이버가 화면을 통째로 `/error/too-many-requests` 로 보내 버렸다.**
그 상태에서는 예약 화면을 아예 못 쓴다 — 정각에 가장 나쁜 일이다. 70번을 초당 14번으로 물은 것은 괜찮았다.
막힘은 그 브라우저에만 걸린 것으로 보인다(같은 인터넷 주소에서 다른 브라우저로는 바로 열렸다). 몇 분 안에 풀렸다.

그래서 간격을 둔다: 시간표 확인은 처음 10초 초당 4번 → 그 뒤 2초에 한 번, 화면 다시 열기는 1.5초에 한 번까지.
막혔다는 답(429·오류 화면)이 오면 20초 쉬고 스스로 예약 화면으로 돌아간다. 정확한 한도는 모른다.

멈추는 경우: 성공 · 못 채운 칸이 있음(직접 채우고 누르면 된다) · 예약 단추를 눌렀는데 화면이 안 바뀜
(화면에 뜬 안내문을 기록에 적는다) · 지켜볼 시간이 지남 · [멈춤].

취소표는 길어야 2초 안에 알아챈다(30분이면 약 900번 확인).

화면 자체의 시간표는 열 때 한 번만 받아 오므로(날짜를 눌러도 다시 안 받는다), 빈 칸을 본 뒤에는
화면을 한 번 다시 열어야 단추가 눌린다. 여는 데 약 0.8초.

## 어디까지 확인했나

| | 어떻게 |
|---|---|
| 기다림 → 새로고침 → 날짜·시간 → 다음단계 | **실제 네이버 화면** (2026-11-16, 자리가 남은 교정 클리닉 상품으로 로그인 화면 직전까지) |
| 두 달에 걸친 주(11-30 ~ 12-04) | 실제 화면 — 달력 끝줄의 다음 달 날짜도 눌린다 |
| 신청서 칸의 모양·예약 단추·완료 주소 | **네이버 화면 코드를 읽어서** 확인 (`ExtraInputForm`·`SubmitButton` 조각). 질문 여섯 개는 병원 설정값 그대로 |
| 신청서 채우기 → 예약 단추 → 완료 화면 | 그 코드와 같은 구조·같은 React 이벤트로 만든 **가짜 신청서**(`mock-request.html`)에서 통과 — 다 채움 / 연습 / 빈 칸 있음 세 경우 |
| **로그인한 진짜 신청서 화면에서 돌려 보기** | **못 했다** — 작업 도구로는 네이버에 로그인한 화면을 열 수 없다. 위 '연습'이 이 확인이다 |
| 여는 시각 전 화면 | **실제 화면** (2026-11-22, 화~토 상품) — 자리 골라 두기 → 시각까지 대기 → 다시 열기까지 확인. 시계를 속여 '4초 전'으로 돌렸다 |
| 진짜 신청서에서 칸 채우기 | **사용자가 확인** (2026-11-22, 교정 클리닉 4칸 중 4칸) |
| 마지막 `동의하고 예약하기` 단추 | 진짜 화면에서는 아직 한 번도 안 눌러 봤다 — 첫 실전이 첫 실행이다 |

## 알아 둔 사실

- 신청서 주소는 `…/items/<상품>/request?startDate=날짜&startDateTime=날짜T시각+09:00` 이다.
  이 주소로 바로 가면 달력 단계를 건너뛸 수 있을지도 모른다 — 써 보지 않았다. 지금 방식이 느리면 다음 수.
- 서버 시계는 응답 `Date` 헤더에서 **초가 넘어가는 순간**을 잡아 맞춘다(시간제보육 확장과 같은 방법).
- 진행 상태·기록은 그 탭에만 남고(탭을 닫으면 사라진다), 아이 정보는 확장 저장소에만 둔다.
- 대시보드 카드는 없다 — 서버가 아니라 사람이 크롬에서 직접 돌리는 도구다.
