# 시간제보육 예약기 (크롬 확장)

아이사랑 예약 화면 위에 작은 패널을 띄워, **9시 정각에 자리를 잡아** 준다.

## 왜 exe 가 아니라 확장인가

아이사랑은 **개발자 도구를 막는다** — 페이지가 `disable-devtool.0.3.7.min.js` 를 올리고
`ondevtoolopen` 으로 대응한다(2026-11-11 확인).

Playwright·CDP·내장 브라우저는 전부 그 개발자 도구를 쓴다. 그래서 붙기만 하면
메인으로 튕기거나 연결이 끊겼다. 이 프로젝트 초반부터 겪은 "메인으로 튕김",
GitHub 서버에서 로그인 화면이 안 뜨던 것, 전용 크롬이 죽던 것이 **전부 같은 원인**이었다.

**확장의 content script 는 개발자 도구를 쓰지 않는다.** 그래서 영향을 받지 않는다.
사이트가 막아 둔 것을 푸는 게 아니라, 애초에 건드리지 않는 길이다.

## 설치 (한 번만, 30초)

1. 크롬 주소창에 `chrome://extensions` 입력
2. 오른쪽 위 **개발자 모드** 켜기
3. 왼쪽 위 **압축해제된 확장 프로그램을 로드합니다** 누르기
4. 이 폴더(`automations/childcare/extension`) 고르기

끝. 크롬을 꺼도 남는다.

## 쓰는 법

평소 쓰는 크롬에서 **로그인한 상태로**:

1. 아이사랑 → 시간제보육 **기관찾기** → 독립반 + 지역 → **조회**
2. 원하는 어린이집의 **시간제보육 예약**
3. **아동 선택** → **이용정보 신청** → **반명** 고르기
   (화면의 `이용시간` 칸은 패널에서 고르면 저절로 따라간다 — 손대지 않아도 된다)
4. 오른쪽 아래 패널에서 **이용일 · 이용 시간 · 오픈 시각** 확인하고 **시작**

그다음은 알아서 한다. 창을 닫거나 다른 페이지로 가지 말 것.

```
┌ 시간제보육 예약기 ──────────┐
│ 이용일    [2026-11-25]      │
│ 이용 시간 [09]시부터 [4]시간 │
│ 오픈 시각 [09:00:00] [ ]즉시 │
│ 미리 감시 [60] 초 전부터     │
│ [  시작  ] [  멈춤  ]       │
│ ─────────────────────────── │
│ 08:59:00 감시 시작          │
│ 08:59:00 아직 그 날짜가     │
│          표에 없어요        │
│ 09:00:00 남은 자리 3개      │
│ 09:00:00 열림 확인 → 발사   │
│ 09:00:01 성공 — 1건 예약 중 │
│          1건 예약되었습니다 │
└─────────────────────────────┘
```

머리글을 누르면 접힌다. 설정은 다음에도 남는다.

### 즉시

`즉시` 를 켜면 시각을 기다리지 않고 **지금부터 지켜보다 자리가 나는 순간 잡는다**.
정해진 시각이 없으므로 보험 한 발은 쏘지 않고, 자리가 보일 때만 쏜다. 한 시간 지켜보고 그만둔다.

쓸 데가 둘이다.
- **취소표 잡기** — 누가 취소하면 그 자리를 먼저 잡는다
- **시험** — 9시를 기다리지 않고 전체가 제대로 도는지 확인한다
  (이미 자리가 있는 날짜·시각으로 켜면 바로 예약되니, 시험이면 끝나고 취소할 것)

**1·2순위를 같이 노리려면** 탭을 두 개 열어 각각 1순위·2순위 예약 화면까지 가 두고
둘 다 [시작]을 누르면 된다. 넷퍼넬 대기열은 탭마다 따로 선다.

## 정각에 무슨 일이 일어나나

```
장전    새로고침(fnRefresh) → 반 다시 고르기 → 칸 누르기 → 추가   ← 사이트의 진짜 버튼
발사    fnSave() 한 번
확인창  뜨는 즉시 누른다 (MutationObserver, 1프레임)
대기열  넷퍼넬 순서를 기다린다 — 여기선 아무것도 안 한다
```

사람이 `새로고침 → 칸 클릭 → 추가 → 예약하기 → 확인` 하는 데 3~5초 걸리는 것을
**0.1초**에 끝낸다.

## 지켜야 할 것

- **연타하지 않는다.** 넷퍼넬(대기열)이 걸려 있어 다시 쏘면 줄 뒤로 밀린다. 한 발만 쏜다.
- **새로고침으로는 줄을 앞설 수 없다.** 넷퍼넬은 `fnSave → insertOcreqst → NetFunnel_Action`
  에서 불린다(함수 안에서 확인). 즉 **`예약하기` 를 누를 때** 줄에 선다 — 페이지를 열거나
  새로고침하는 것만으로는 그 코드가 돌지 않는다.
  그리고 대기 화면에 사이트가 직접 이렇게 적어 둔다(netfunnel-skin.js 에서 읽음):
  > 새로고침, 뒤로가기 또는 재접속하시면 대기시간이 더 길어집니다.

  대기 중에는 아무것도 누르지 않는 것이 맞다 — 기록창에
  `대기열 — 앞에 842명 · 예상 0시간 1분 20초` 로 보인다.
- **자리 조회는 대기표를 쓰지 않는다.** 그래서 마음 놓고 지켜볼 수 있다.
- **오픈 시각을 안다고 전제하지 않는다.** 공식 안내는 "이용일 14일 전 09:00" 이지만
  초 단위는 모르고 기관마다 다를 수 있다. 그래서 예상 시각 전부터 가볍게 지켜보다가
  **열리는 순간** 쏘고, 예상 정각에도 보험으로 한 발 쏜다.
- **자리 확인은 가볍다.** 표 전체가 한 번에 오는 요청 하나다. 0.25초 간격 24번을
  찔러도 막히지 않았다(실측, 전부 200 OK · 응답 크기 동일 · 느려지지 않음).

## 알아 둔 사실 (실측)

- 칸 번호는 "오늘부터 며칠 뒤"가 **아니다**. 당일 마감(14시)이 지나면 오늘이 표에서 빠진다.
  그래서 줄에 적힌 **날짜로** 찾는다.
- 자리 숫자 = 더 받을 수 있는 아동 수. `0` 이면 자리 없음, `X` 는 운영 안 함.
- 이 PC 시계는 서버와 수백 ms 어긋난다. 응답 `Date` 헤더는 초 단위라,
  **초가 넘어가는 순간**을 잡아 ms 까지 맞춘다(8번 재서 가장 작은 값, 편차 6ms).
- 성공 문구: `1건 예약 중 1건 예약되었습니다.`

## 고칠 때

전부 `engine.js` 한 파일이다. 고친 뒤 `chrome://extensions` 에서 **새로고침**(↻) 누르고
아이사랑 페이지를 새로고침하면 반영된다.

## 겪은 함정

- **`이용정보를 선택해 주시기 바랍니다`** — 숨은 값을 직접 채워 넣는(장전) 방식을 썼다가 막혔다.
  처음 손으로 성공했을 때는 앞서 진짜 `추가` 를 눌렀다 지운 화면이라, 사이트가 남긴 무언가가
  더 있었던 것이다. `이용시간`(`#rtm`) 을 채워도 마찬가지였다.
  → **사이트의 진짜 버튼을 그대로 누른다.** 중복 확인 왕복이 한 번 더 들지만 확실하다.
- 거절 사유는 평범한 알림창(`layer-popup-contents`)으로도 온다 — 둘 다 받아 적는다.

## 막혔을 때 보는 법

기록창에 **사이트가 한 말이 그대로** 남는다. 그게 유일한 단서다.

| 기록창 | 뜻 |
|---|---|
| `추가 거절 — 이미 예약된 시간입니다.` | 그 아동이 그 시간에 이미 예약(또는 이력)이 있다. 다른 날짜·시각으로 |
| `2026-11-26 줄이 화면 표에 없어요` | 아직 안 열렸다. 정상 — 기다리면 된다 |
| `09시 자리가 없어요 (0)` | 그 시각은 찼다 |
| `09시 칸이 없어요` | 그 기관이 그 시각에 운영하지 않는다 |
| `시간표가 비어 있어요 — 로그인이 풀렸는지…` | 로그인이 풀렸다. 다시 로그인하고 [시작] |
| `열 번 내리 실패했어요` | 같은 실패가 계속된다 |

세 번 실패하면 스스로 멈춘다 — 중복 같은 사유는 다시 해도 안 되기 때문이다.

### 세션은 1시간 (2026-11-11 실측)

기록창의 `세션 남은 시간` 은 아이사랑이 심는 전자정부 쿠키
(`egovLatestServerTime`·`egovExpireSessionTime`)를 읽은 것이다. 실제 로그에서 확인했다.

- **세션 길이는 1시간.** 남은 시간이 늘 `59분 59초` 로 나온다
- `마지막 갱신` 이 읽는 순간과 항상 같다 = 계속 새로 고쳐지고 있다
- 사용자 관찰로는 **1시간이 되면 풀리는 듯하다** — 그래서 너무 일찍 켜 두면 위험하다

**[시작] 할 때 발사 시각까지 세션이 버티는지 따져 보고, 모자라면 경고한다.**

```
⚠ 발사 전에 로그인이 풀릴 수 있어요 (세션 약 2분 남음)
⚠ 다시 로그인한 뒤 [시작]을 눌러 주세요
```

지켜보는 중에 3분 아래로 떨어져도 한 번 알린다.
**9시에 쓸 거면 8시 50분쯤 로그인하고 시작하는 것이 맞다.** 밤새 켜 두지 말 것.

### 로그인은 안 끊기나

자리 조회도 로그인 쿠키를 들고 가는 요청이라, 지켜보는 동안 **세션 시계가 계속 초기화된다.**
가만히 두는 것보다 오히려 안전하다.

그래도 풀릴 수는 있다(다른 곳에서 로그아웃, 사이트 쪽 만료 등). 그때 조회는
**시간표 대신 로그인 화면**을 받아 오는데, 예전에는 그걸 "아직 날짜가 안 열렸다" 로 읽어
한 시간 내내 조용히 헛돌았다. 지금은 날짜 줄이 **하나도** 없으면 바로 알려 준다.

|---|---|
| `NetFunnel_Skin_Top` | 대기 화면 전체 (이게 보이면 줄 서는 중) |

**누르지 않는다.** 보기만 한다.

## 새로고침은 우리가 대신 누른다

헷갈리기 쉬운 곳이라 적어 둔다. 하는 일이 둘로 나뉜다.

| | 무엇 | 화면을 바꾸나 |
|---|---|---|
| **감시** | `occasionCrTmInfoAjax` 직접 호출 | **아니다.** "언제 열렸나" 만 본다 |
| **장전** | `fnRefresh()` → 반 다시 고르기 → 칸 클릭 → 추가 | 그렇다. 화면 그대로 조작한다 |

`새로고침` 버튼의 `onclick` 이 `fnRefresh()` 다 — 우리는 그 함수를 그대로 부른다.
**새로고침 없이 뒷단 값만으로 예약하지 않는다.**

새로고침해도 **반 설정은 그대로다**(사용자 확인 2026-11-11). 그래서 반을 비웠다 고르는 짓은
하지 않는다 — 비우는 순간 사이트가 경고를 띄울 수 있다.
대신 값은 그대로 두고 **`change` 만 다시 일으켜** 표를 다시 달라고 한다(`askGridAgain`).
새로고침만으로 6초 안에 줄이 생기면 그걸 쓰고, 안 생기면 그때만 한 번 더 조른다.

## 열림 감지 — 무엇을 주고받나

```
POST /icms/occasion/occasionCrTmInfoAjax.html
     Content-Type: application/x-www-form-urlencoded
     X-Requested-With: XMLHttpRequest
     chilinnb=<아동번호>&stcode=11710000741&clseq=15      ← 화면의 #pfrm 에서 그대로 꺼낸 값 3개
          ↓  약 24KB HTML (2026-11-11 실측: 24,688바이트 고정, 왕복 평균 361ms)
<tr><td>2026-11-25(수)</td><td><a class="time-option" id="tm_9_0">0</a>…
<tr><td>2026-11-26(목)</td><td><a class="time-option" id="tm_9_1">3</a>…
```

판정은 단순하다.

| 응답에 | 뜻 | 하는 일 |
|---|---|---|
| 그 날짜 줄이 **없다** | 아직 안 열림 | 기다린다 (`-1`) |
| 줄은 **있는데** 해당 시각 칸이 `0`·`X` | 열렸지만 자리 없음 | 기다린다 |
| 칸이 **1 이상** | **열렸고 자리 있음** | 장전 → 발사 |
| 날짜 줄이 **하나도 없다** | 시간표를 못 받음 | 로그인 끊김으로 본다 |

즉 **"그 날짜 줄이 응답에 처음 등장하는 순간"** 이 서버가 연 시각이다.
화면은 건드리지 않으므로 몇 번을 물어도 사람이 보는 화면은 그대로다.

## 자리 숫자가 보여도 예약이 되는 건 아니다 (2026-11-12)

자정이 지나면 **그날의 14일 뒤 줄이 미리 생기고 자리 수까지 보인다.**
11월 12일 0시 넘어 확인하니 `2026-11-26` 줄이 있고 09시 칸이 `3` 이었는데, 신청은 안 됐다.

그래서 `자리 1개 이상 = 열림` 은 **틀린 판단**이다. 그대로 두면 8시 59분에 쏴서
세 번 실패하고 멈춰, 정작 9시에 아무것도 못 한다.

→ **정해진 발사 시각 전에는 쏘지 않는다.** 자리가 보여도 기다리고 한 줄만 남긴다.

```
자리 3개가 보이지만 아직 발사 시각 전이라 기다립니다
```

`즉시` 를 켠 경우에만 시각과 무관하게 쏜다(취소표 잡기용).

## 미리 장전하고 정각엔 예약하기만 (2026-11-12, 지금 방식)

**`추가` 는 9시 전에도 된다. 막히는 것은 `예약하기` 뿐이다**(사용자 확인).
그래서 기다리는 동안 새로고침·칸 클릭·추가를 전부 끝내 두고,
정각에는 **`예약하기` 한 번만** 누른다. 임계 경로에서 1초 넘게 빠진다.

```
08:5x  새로고침 → 칸 클릭 → 추가        ← 여기까지 미리
       "미리 장전 완료 — 정각에 예약하기만 누릅니다"
08:59:55  예약하기 (0.4초 간격으로 반복)
          "아직예약가능한 시간이 아닙니다"  ← 손해 없다. 계속 누른다
09:00:00  통과 → 대기열 → 성공
```

오픈 시각을 정확히 맞출 필요가 없다 — **될 때까지 누르면 된다.**
5초 일찍 시작하고, 정각 뒤 10분까지 누른다(`RETRY_MS`·`RETRY_WINDOW_MS`).

멈추는 경우는 둘뿐이다.
- **성공**
- 거절 사유가 "아직…" 이 아닐 때 (예: `이미 예약된 시간입니다`) — 다시 해도 안 되므로

**대기열에 서 있는 동안은 다시 쏘지 않는다.** `NetFunnel_Skin_Top` 이 보이면
응답을 끝까지 기다린다. 여기서 포기하고 다시 쏘면 대기표를 버리고 맨 뒤로 간다.

## 예약하기를 누르면 창이 두 번 뜬다

실제 화면에서 눌러 보고 확인했다(2026-11-12 00:30, 아직 안 열린 11-26 으로).

```
예약하기(fnSave) → insertOcreqst()
```

### 함정 둘 (둘 다 실제 화면에서만 드러났다)

1. 거절 문구는 `layer-popup-contents` 가 아니라 **`layer-alert-popup-contents2`** 에 뜬다.
   안 보고 있으면 응답을 못 읽고 한 번 쏜 뒤 멈춘다.
2. **같은 id 가 문서에 두 벌씩 있다** — 숨은 것과 보이는 것.
   `getElementById` 는 첫 번째(숨은 것)를 집으므로 글도 못 읽고 확인도 못 누른다.
   → 같은 id 를 전부 훑어 **보이는 것**을 쓴다.

**둘을 가르지 않으면 "예약하시겠습니까?" 를 결과로 착각해 성공을 실패로 읽는다.**
id 로 가른다 — `layer-confirm-popup-*` 는 누르기만 하고, `layer-popup-*` 만 답으로 본다.
