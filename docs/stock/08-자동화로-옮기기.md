# 8단계 — 자동화로 옮기기 (설계 초안)

1~7단계에서 "설계로 넘길 것"을 모아 만든 초안. **아직 승인 전**이며 코드는 없다. 사용자가 맨 아래 결정 사항을 정하면 정식 설계서(`docs/superpowers/specs/`)로 옮기고 `/new-automation` 절차로 만든다.
작성일: 2026-09-21.

## 1. 한 줄 요약

미국 장이 끝나면(한국 아침) S&P 500 전 종목의 일별 시세를 새로 받아, 켜 둔 규칙으로 **새로 살 후보**와 **팔 때가 된 보유 종목**을 계산해 텔레그램으로 보낸다. 주문은 사용자가 미래에셋 앱에서 직접 한다. 사이트에는 건수만 보인다.

## 2. 어디에 붙이나

- 사무실: **홈(`/home`)의 자산·투자팀(`finance`)**. 부서가 이미 있고 지금은 숨김 상태다. 새 사무실을 만들 필요가 없다.
- 자동화 id `signal`, 카드 이름 "매매 신호". 직원(하위 작업) 셋:

  | id | 업무명 | 하는 일 |
  |---|---|---|
  | `quotes` | 시세 수집 | 구성 종목 목록·일별 시세·실적 일정 받기 |
  | `scan` | 신호 계산 | 규칙 적용, 크기·손절 값 계산 |
  | `notify` | 알림 전송 | 텔레그램 발송, 건수 기록 |

- 개인 폴더 `ai-home/NN_매매신호/`(README 와 개인 설정. gitignore 로 이미 막혀 있다).

## 3. 하루 흐름

```
UTC 21:30 (한국 06:30, 화~토)  Cloudflare 예약 → signal.yml 실행
  1 시세 수집   위키 구성 종목(실패 시 직전 목록) → 야후 일별 시세 1.5년치 통째로
                → 나스닥 실적 달력 2주치 → 지수·VIX·환율
                실패 종목 5% 넘으면 여기서 중단(신호 없음, 오류 알림)
  2 신호 계산   시장 상태(지수 200일선, VIX 구간)
                켜 둔 규칙마다: 새로 살 후보(점수순, 하루 상한) / 보유 종목 청산 조건
                후보마다: 기준 가격, 무효 조건, 권장 크기, 손절 값, 실적 발표 D-N, 업종
  3 알림 전송   텔레그램 한 통. 같은 미국 날짜로 이미 보냈으면 다시 보내지 않음
                상태 파일·실행 일지에는 "후보 3건, 청산 1건" 같은 건수만
```

- 예약: `worker/schedule.ts` 에 `{ workflow: "signal.yml", cron: "30 21 * * 1-5" }`. 미국 폐장(UTC 20:00 또는 21:00) 뒤라 서머타임을 계산하지 않아도 된다. 미국 휴장일에는 마지막 봉 날짜가 그대로라 "새 데이터 없음 — 쉬는 날"로 끝낸다(오류 아님).
- **시작 버튼**: 누가 눌러도 나가는 것은 주문이 아니라 계산이다. 같은 날짜 알림은 한 번만 보내므로 중복 알림도 없다. 다른 자동화와 같게 버튼을 그대로 둔다.
- 실행 위치: 기본 GitHub 서버(`ubuntu-latest`). 첫 시험에서 야후가 요청을 막으면 사무실 PC 실행기로 바꾼다(2단계 미확인 항목).

## 4. 알림 모양 (예시 — 종목·숫자는 가짜)

```

시장: 지수 200일선 위 · VIX 14.8(낮음) · 환율 1,385원(+0.2%)
오늘 밤: 주요 발표 없음

▶ 새로 살 후보 2 (규칙 R2b, 매월 말)
1. AAAA  정보기술 · 기준가 $123.40
   무효: 시가가 $127.10 넘으면 건너뜀 · 손절 $111.00 · 권장 크기 계좌의 8%
   실적 발표 D-12
2. BBBB  산업재 · …

■ 팔 때가 된 보유 종목 1
- CCCC  순위 밖으로 밀림(R2b 청산 조건) · 오늘 밤 시가 매도 기준

이번 달 신호 5 · 연속 손실 2(검증상 최대 18)
주문은 직접 넣으세요. 이 알림은 규칙의 계산 결과이며 투자 권유가 아닙니다.
```

## 5. 코드 구성 (`automations/signal/`)

| 파일 | 역할 | 성격 |
|---|---|---|
| `signal_data.py` | 구성 종목·시세·실적 일정·시장 지표 받기, 실패율 검사, 이상값 거르기 | 바깥과 통신 |
| `signal_indicators.py` | 이동평균·모멘텀·RSI·ATR·신고가 | 순수 함수 |
| `signal_rules.py` | 규칙 설정 → 진입·청산·점수 계산 | 순수 함수 |
| `signal_risk.py` | 권장 크기·손절 값·업종 쏠림·연속 손실 | 순수 함수 |
| `signal_holdings.py` | 보유 목록 읽기(아래 6번) | 바깥과 통신 |
| `signal_message.py` | 알림 글 만들기, 공개용 건수 요약 | 순수 함수 |
| `signal_backtest.py` | 같은 규칙 설정으로 과거 검증(7단계 재현) | 손으로만 실행 |
| `rules.yaml` | 규칙 정의(R1~R4b)와 켜짐 여부, 하루 상한, 실적 임박 처리 | 설정 |
| `run_signal.py` | 템플릿의 `do_work()` | 뼈대 |

- 모듈 이름에 `signal_` 을 붙인다(다른 자동화와 이름이 겹치면 pytest 에서 서로 가린다).
- 순수 함수는 작은 가짜 시세로 테스트한다(교차가 일어나는 날, 이력이 짧은 종목, 분할 있는 종목, 빈 데이터).
- 텔레그램은 `automations/common/telegram_bot.py` 의 `send_message` 를 그대로 쓴다.
- 새 의존성: `yfinance`, `pandas`, `lxml`. 워크플로에서 설치.

## 6. 공개 저장소에서 개인 정보를 지키는 법

| 정보 | 두는 곳 |
|---|---|
| 규칙 정의(R1~R4b 의 조건식) | 저장소(`rules.yaml`). 교과서 규칙이라 공개돼도 무방 |
| **어떤 규칙을 켰는지, 계좌 기준액, 허용 손실 %** | GitHub Secret `SIGNAL_SETTINGS`(짧은 JSON) |
| **보유 종목**(청산 신호에 필요) | 드라이브의 구글 시트 한 장(사용자가 휴대폰에서 고침). 시트 id 는 Secret `SIGNAL_SHEET_ID`. 기존 `GOOGLE_*` 인증을 재사용 |
| 신호 내용(종목·값) | 텔레그램으로만 |
| 상태 파일·실행 일지 | 건수만("후보 2, 청산 1") |
| 시세 | 저장하지 않음 |

- 보유 시트 열: 티커 · 산 날 · 산 값 · 규칙 이름 · (선택) 수량. 사고판 뒤 사용자가 한 줄 고친다. 이 시트가 "신호를 따랐는지"의 기록도 겸한다(6단계 7번).
- 관찰 모드 동안에는 시트 대신 **가상 보유 목록**(신호를 전부 따랐다고 가정)을 드라이브에 둔다.

## 7. 새 비밀값

| 이름 | 용도 | 비고 |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | 발송 | 이미 있음(주말 일정에서 사용) |
| `TELEGRAM_CHAT_ID_SIGNAL` | 받을 대화방 | 새로. 다른 알림과 섞이지 않게 방을 따로 둘지 사용자 결정 |
| `SIGNAL_SETTINGS` | 켠 규칙·계좌 기준액·허용 손실 % | 새로 |
| `SIGNAL_SHEET_ID` | 보유 시트 | 새로. 관찰 모드에는 없어도 됨 |
| `GOOGLE_*` | 드라이브·시트 인증 | 이미 있음 |

## 8. 단계별로 만든다

1. **1차 — 관찰 모드**: 시세 수집 → 규칙 계산 → 텔레그램. 가상 보유 목록. 크기·손절 값 포함. 검증 코드 포함.
2. **2차 — 실제 보유 연결**: 구글 시트, 청산 신호가 실제 보유 기준으로.
3. **3차 — 월간 복기**: 매월 첫 실행 때 지난달 신호·규칙 성적·지수 비교를 한 통으로.
4. 나중: 한국 종목(네이버 시세, 코스피200 등 대상 정하기), 재무 기반 규칙.

## 9. 하지 않는 것

- 자동 주문(미래에셋에 개인용 API 가 없고, 이 프로젝트의 결정이 알림형이다).
- 장중 실시간 신호(구조상 수십 초~몇 분 늦다. 일봉 규칙만).
- 규칙 숫자를 과거에 맞춰 고르는 기능.
- 종목 추천·전망 글(알림은 규칙의 계산 결과만 적는다).

## 10. 사용자가 정해야 하는 것

AI 가 대신 고르지 않는 항목이다. 7단계 표를 근거로 정한다.

1. **켤 규칙** — R1(지수 추세) / R2(모멘텀) / R2b(모멘텀 + 시장 필터) / R4b(신고가 돌파 + 시장 필터) 중 하나 이상. R3(눌림목)는 수수료가 편도 0.05% 아래가 아니면 성립하지 않는다.
2. **견딜 수 있는 최대 낙폭**과 규칙 매매에 둘 금액 — 크기 계산의 기준.
3. **실적 발표 임박 종목**: 신규 매수 후보에서 뺄지, 경고만 달지. 며칠 전부터로 볼지.
4. **텔레그램 방**을 따로 만들지.
5. **관찰 기간** 길이(권장 범위 2~3개월, 월 1회 규칙이면 더 길게).

미래에셋 앱에서 확인할 것(1단계 9번)도 이때 같이: 내 수수료율, 미국주식 조건 매도 주문 가능 여부, 예약주문.
