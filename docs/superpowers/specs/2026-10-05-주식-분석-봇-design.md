# 주식 분석 봇 설계 (2026-10-05)

기사·공시, 재무제표, 시세를 한데 모아 애널리스트처럼 종목을 점검하고, AI 오피스 사이트에서 보여 주는 자동화.
화면 시안: 클로드 디자인 캔버스 "주식 분석 봇 화면 시안"(관심 종목 판 · 발굴 판 · 종목 한 장, 2026-10-02 종가 기준 실제 숫자).

## 1. 사용자 결정 (2026-10-05 대화)

| 항목 | 결정 |
|---|---|
| 용도 | ① 보유·관심 종목을 매일 점검 ② 조건에 맞는 새 종목 발굴 |
| 시장 | 미국·국내 둘 다. 화면은 처음부터 두 시장을 담고, 수집은 미국 먼저 → 국내 |
| 발굴 관점 | 싸고 탄탄 · 실적 개선 · 사건 · 돈 몰림 전부. 기본 정렬은 여러 관점에 겹친 순 |
| 의견 모양 | 등급·목표가를 내지 않는다. 좋게 보는 근거와 나쁘게 보는 근거를 나란히 + 점검표 |
| AI 비용 | **매일 자동으로 도는 부분은 AI 호출 없음(무료).** 해석은 사용자가 클로드 대화에서 "○○ 해석해 줘"라고 할 때만 쓰고, 저장해서 사이트에 반영 |
| 받는 곳 | 사이트만 (알림 없음) |
| 관심 종목 관리 | 사이트에서 직접 담고 뺀다 |
| 구조 | 지금 AI 오피스에 얹는다 (GitHub Actions 수집·계산 → 비공개 저장 → 사이트 화면) |

## 2. 범위

**만드는 것**

- 홈 사무실 `자산·투자팀`에 자동화 카드 "주식 분석" 1개와, 거기서 들어가는 화면 3개(관심 종목 판, 발굴 판, 종목 한 장).
- 매일 도는 수집·계산 프로그램(미국, 국내).
- 해석을 저장하고 채점하는 흐름.

**만들지 않는 것**

- 매수·매도 추천, 등급, 목표가 산출. 주문 기능.
- 알림(텔레그램 등). 나중에 얹을 수 있게 막지만 않는다.
- 장중 실시간 갱신. 하루 한두 번 갱신한다.
- 로그인. 지금 사이트와 같다(주소를 아는 사람은 보고 고칠 수 있다).

기존 `automations/stock/`(미국 주식 매매신호, 보류 중)과는 별개다. 새 자동화 id 는 `analyst`.

## 3. 화면

모양은 지금 대시보드(`app/dashboard.css`)의 토큰과 글꼴을 그대로 쓴다. 상태는 색 + 아이콘 + 글자를 함께 쓴다.

### 3.1 관심 종목 판 `/home/stock`

- 머리: 화면 전환(관심 종목 · 발굴), 시장 전환(미국 · 국내), 기준 시각.
- "오늘 먼저 볼 것" 3칸: 30일 안에 실적 발표가 있는 종목, 경고가 가장 많은 종목, 1년 최고가 3% 안쪽 종목. 해당이 없으면 그렇다고 적는다.
- 목록(종목당 한 줄): 이름·기호, 현재가·전일 대비, 1년 흐름선, 고점 대비, 예상 PER, 점검표 개수(통과·주의·경고), 점검 요약, 다음 실적일, "분석 보기".
- 종목 추가 칸(이름이나 기호로 찾기)과 빼기.

### 3.2 발굴 판 `/home/stock/discover`

- 관점 단추 5개: 전체 · 싸고 탄탄 · 실적 개선 · 사건 · 돈 몰림. 단추마다 걸린 종목 수.
- 단추 아래에 지금 보는 관점의 기준을 한 줄로 적는다.
- 카드: 이름·가격, "관점 N개"와 걸린 관점 이름, 관점별로 걸린 이유 한 줄, 핵심 숫자 4개(예상 PER, 매출 증가, 빚, 거래대금 배수), "관심에 담기", "분석 보기".
- 전체에서는 겹친 관점 수가 많은 순.

### 3.3 종목 한 장 `/home/stock/<시장>/<기호>`

위에서 아래로:

1. 이름·기호·거래소, 현재가, 발굴에 걸린 관점, 관심 담기·빼기.
2. **한 줄 결론.** 해석이 저장돼 있으면 "AI 해석 · 작성일"과 함께 그 문장을, 없으면 점검표로 만든 규칙 문장("좋음: … / 경고: …")을 보인다. 해석이 오래됐으면(§6.3) 표시를 붙인다.
3. 좋게 보는 근거 · 나쁘게 보는 근거(나란히). 해석이 없으면 점검표의 통과·경고 항목을 숫자와 함께 나열한다. 근거마다 출처 꼬리표(재무 · 시세 · 뉴스 · 전망).
4. 점검표 7가지(§5.1).
5. 주가와 사건: 1년 종가 선 그래프 + 번호 찍힌 사건, 아래에 번호별 설명.
6. 가치 견주기: 예상 PER 을 같은 업종 회사·업종 중앙값과 막대로. PER · 예상 PER · PBR · 평균 목표가.
7. 실적과 재무 4년 흐름: 매출, 순이익, 설비 투자, 쓰고 남은 현금.
8. 다음 일정(실적 발표일).
9. 의견 기록과 채점(§6.4).
10. 출처와 기준일, "투자 권유가 아님" 문구.

## 4. 자료와 흐름

### 4.1 출처 (전부 무료)

| 자료 | 미국 | 국내 |
|---|---|---|
| 시세·거래대금 | 야후 파이낸스(yfinance) | 네이버 금융 목록·시세 |
| 재무제표·가치 지표 | 야후 파이낸스 | 전자공시(DART) 오픈 API (인증키 필요) |
| 공시 | 미국 증권거래위원회(EDGAR) 최근 제출 목록 | DART 공시 목록 |
| 뉴스 제목 | 구글 뉴스 RSS (기사 수집 자동화와 같은 방식) | 같음 |
| 실적 발표일·평균 목표가 | 야후 파이낸스 | 구할 수 있는 범위만, 없으면 비움 |

2026-10-06 결정: 국내도 야후 파이낸스로 받는다(네이버·DART 는 보류, 이유는 4단계 계획 `docs/superpowers/plans/2026-10-06-주식-분석-봇-4단계-국내.md`).

### 4.2 대상

- 발굴 대상: 미국 대표 대형주 약 500개, 국내 코스피·코스닥 대표 종목 약 350개. 목록은 설정 파일에 둔다.
- 관심 종목은 대상 밖 종목도 담을 수 있다. 담긴 종목은 다음 갱신 때 같이 수집한다.

### 4.3 갱신

예약은 `worker/schedule.ts` 에 넣는다(워크플로에 cron 금지).

| 워크플로 | 시각(KST) | 하는 일 |
|---|---|---|
| `analyst.yml` (market=us) | 화~토 07:00 | 미국 시세·거래대금·공시·뉴스 제목, 계산, 저장 |
| `analyst.yml` (market=kr) | 월~금 16:30 | 국내 같은 일 |
| `analyst.yml` (mode=fundamentals) | 토 09:00 | 두 시장 재무제표·가치 지표·실적일 다시 받기 (미구현 — 매일 전부 다시 받는다) |

재무 자료는 주 1회, 가격 자료는 매일. 실적 발표 직후 종목은 매일 실행에서 그 종목만 재무를 다시 받는다.

### 4.4 계산은 프로그램, 문장은 틀

매일 실행에서는 AI 를 부르지 않는다. 숫자는 전부 코드가 계산하고, 화면 문장은 틀에 숫자를 끼워 만든다("예상 PER 12.9배 · 업종 중앙값 24.0배보다 낮음").
사건 분류는 공시 종류 코드로 한다(실적, 자금 조달, 인수합병, 대표 교체, 소송 등). 기사 제목은 요약하지 않고 그대로 나열하되 같은 제목은 하나로 묶는다.

### 4.5 저장과 공개 범위

- 저장: R2 버킷 `ai-office-live`(바인딩 `LIVE`)의 `stock/` 아래.
  - `stock/<시장>/board.json` 관심·발굴 판용 요약(종목당 한 줄 분량)
  - `stock/<시장>/t/<기호>.json` 종목 한 장용 자료
  - `stock/watchlist.json` 관심 목록
  - `stock/opinions/<시장>/<기호>.json` 해석과 채점 기록
  - `stock/lens-log/<시장>/<YYYY-MM-DD>.json` 하루 한 파일, 관점별로 걸린 종목 기록(§5.3)
- 공개 저장소에 올라가는 상태 파일·일지에는 **건수만** 남긴다("미국 500종목 점검, 후보 12종목"). 종목 이름·관심 목록·해석은 넣지 않는다. 실행 로그에도 종목별 내용을 찍지 않는다.
- "비공개"의 뜻: 공개 저장소에 없다는 것. 사이트에 로그인이 없으므로 사이트 주소를 아는 사람은 볼 수 있다(지금 호가 화면과 같은 조건).

### 4.6 Worker 경로

| 경로 | 쓰는 쪽 | 하는 일 |
|---|---|---|
| `GET /api/stock?market=&view=board` | 화면 | 판 요약 + 관심 목록 |
| `GET /api/stock?market=&ticker=` | 화면, 클로드 | 종목 한 장 자료 + 해석 |
| `POST /api/stock/watch` | 화면 | 관심 담기·빼기 (기호 형식 검사, 최대 100종목) |
| `POST /api/stock/ingest` | 수집 프로그램 | 판·종목 자료 저장 |
| `POST /api/stock/opinion` | 클로드(해석 저장 스크립트) | 해석 저장 |

`ingest`·`opinion` 은 `/api/live` 와 같은 방식으로 Worker 비밀값 `LIVE_TOKEN` 이 있으면 검사하고 없으면 검사 없이 받는다(사용자 결정 2026-09-29 와 같은 운영).

## 5. 점검표와 발굴 기준

원칙: 절대 숫자 대신 같은 업종과 견준다. 기준은 화면에 적는다. 문턱값은 설정 파일 한 곳(`automations/analyst/rules.yaml`)에 둔다. 자료가 없으면 "자료 없음".

### 5.1 점검표 7가지

| 항목 | 통과 | 주의 | 경고 |
|---|---|---|---|
| 가치 | 예상 PER < 업종 중앙값 | 업종 중앙값 ~ 1.5배 | 업종 중앙값의 1.5배 이상, 또는 적자 |
| 매출 성장 | 전년 대비 +10% 이상 | 0~10% | 감소 |
| 이익 방향 | 증가 | 0 ~ −20% | −20% 아래, 또는 적자 지속 |
| 수익성 | 영업이익률 ≥ 업종 중앙값 | 흑자지만 업종보다 낮음 | 영업적자 |
| 빚 | 순부채 < 연간 영업이익(EBITDA)의 2배 | 2~4배 | 4배 이상 |
| 현금흐름 | 쓰고 남은 현금(FCF) 흑자 | 영업현금은 흑자, FCF 적자 | 영업현금 적자 |
| 추세 | 1년 최고가의 10% 안쪽 | 10~30% 아래 | 30% 넘게 아래 |

업종은 미국은 야후 파이낸스의 업종 분류, 국내는 네이버 금융의 업종 분류를 쓴다. 금융업(은행·보험·증권)은 빚·현금흐름을 "해당 없음"으로 둔다. 업종 안 종목이 5개 미만이면 시장 전체 중앙값과 견준다.

### 5.2 발굴 네 관점

| 관점 | 기준 |
|---|---|
| 싸고 탄탄 | 가치·빚·현금흐름이 모두 통과 |
| 실적 개선 | 매출 +15% 이상이면서 이익 증가, 또는 최근 실적이 전문가 예상을 넘음(자료가 있을 때) |
| 사건 | 최근 2주 안에 주요 공시가 있었거나, 하루 ±7% 이상 움직이면서 거래대금이 60일 평균의 3배 이상 |
| 돈 몰림 | 최근 5일 평균 거래대금이 60일 평균의 1.5배 이상이고 종가가 20일 평균 위 |

### 5.3 기준 채점

관점에 걸린 종목과 그날 종가를 매일 기록하고, 1주·1개월·3개월 뒤 수익률을 시장 지수와 견줘 쌓는다. 발굴 판 아래에 관점별 성적(걸린 횟수, 평균 초과수익, 이긴 비율)을 보인다. 표본이 30건 미만이면 "아직 판단하기 이름"으로 적는다. 문턱값 조정은 이 성적을 보고 사람이 한다.

## 6. 해석 ("○○ 해석해 줘")

### 6.1 절차

프로젝트 스킬 `.claude/skills/stock-opinion/` 로 고정한다.

1. `GET /api/stock?ticker=` 로 그 종목의 계산값·공시·기사 제목을 읽는다.
2. 필요하면 기사 본문·실적 발표 자료를 찾아 읽는다.
3. 한 줄 결론, 좋게 보는 근거 3~4개, 나쁘게 보는 근거 3~4개, 다음 실적에서 볼 것을 쓴다.
4. `python automations/analyst/save_opinion.py <시장> <기호> --file <json>` 으로 저장한다(Worker `opinion` 경로).
5. 사이트 종목 한 장에서 반영을 확인하고 사용자에게 알린다.

### 6.2 지킬 것

- 문장 속 숫자는 저장된 계산값에서만 가져온다. 계산값에 없는 숫자를 쓰려면 출처를 붙인다.
- 등급·목표가·"사라/팔아라"를 쓰지 않는다. 근거와 갈림길(무엇이 확인되면 좋아지고 나빠지는지)을 쓴다.
- 근거마다 출처 종류(재무 · 시세 · 뉴스 · 전망)를 붙인다.

### 6.3 오래된 해석

해석을 쓴 뒤 실적 발표가 있었거나, 30일이 지났거나, 주가가 작성일 대비 ±20% 넘게 움직였으면 "해석이 오래됨 — 새 자료가 나왔어요" 표시를 붙인다. 해석 자체는 지우지 않는다.

### 6.4 의견 채점

해석마다 작성일·당시 주가·결론을 남긴다. 종목 한 장에 지난 해석 목록과, 작성 뒤 1주·1개월·3개월 수익률(시장 지수 대비)을 보인다. 해석은 등급이 없으므로 맞고 틀림을 자동으로 매기지 않고, 수익률만 나란히 보여 사람이 판단한다.

| `app/stock-rules.ts` | 화면용 순수 규칙(정렬, 오래된 해석 판정, 문구) + 시험 |
| `app/workspaces/home.ts` | `{ id: "analyst", dept: "finance", name: "주식 분석", workflow: "analyst.yml", tasks: [collect, check, discover] }` + 카드에서 화면으로 가는 단추 |
| `.claude/skills/stock-opinion/` | 해석 절차 |

순수 계산(`metrics`·`checks`·`events`)은 수집과 분리해 고정 자료로 시험한다.

## 8. 오류 처리

- 한 종목 수집 실패는 그 종목만 "자료 없음"으로 두고 계속한다. 실패가 대상의 20%를 넘으면 실행을 실패로 보고하고, 판은 지난 자료를 그대로 둔다(기준 시각이 화면에 보이므로 오래된 것이 드러난다).
- 야후 파이낸스가 GitHub 서버를 막으면 사무실 PC 실행기(`kr-office`)로 옮긴다. 국내 시세도 해외 IP 를 막으면 같은 실행기를 쓴다.
- 저장 공간이 연결되지 않았으면 화면에 "아직 연결되지 않았어요"를 보인다(`/api/live` 와 같은 문구 방식).
- 관심 종목 추가 때 대상 목록에 없는 기호는 다음 갱신 전까지 "자료를 받는 중"으로 보인다.

## 9. 단계

각 단계가 끝나면 사이트에서 쓸 수 있다.

1. **미국 관심 종목**: 수집·계산·저장, 관심 종목 판, 종목 한 장(규칙 문장), 관심 담기·빼기.
2. **미국 발굴**: 대상 500종목, 발굴 판, 기준 채점 기록 시작.
3. **해석**: 해석 저장·반영·오래됨 표시·의견 채점, `stock-opinion` 스킬.
4. **국내**: DART 키 발급 안내, 국내 수집, 시장 전환.

## 10. 확인 방법

- `python -m pytest -q automations/analyst` (지표·점검표·관점·공시 분류, 고정 자료)
- `bash scripts/npm.sh tsc` · `test` · `build`
- 개발 서버에서 화면 3개와 휴대폰 너비, 자료 없음·저장 공간 없음 상태
- 실제 실행 1회 뒤 숫자 5종목을 야후 파이낸스 화면과 맞대어 확인
- 공개 상태 파일·실행 로그에 종목 이름이 없는지 확인

## 11. 알려진 한계

- 야후 파이낸스 재무 숫자는 회사 발표와 조금 다를 수 있다. 화면에 출처와 기준일을 붙인다.
- AI 없이 도는 날의 "사건"은 공시 종류와 기사 제목까지만이다. 왜 중요한지는 해석을 요청해야 나온다.
- 지난 연구(`docs/stock/` 1~15번)에서 단순 신호는 비용을 넘지 못했다. 이 봇은 수익을 약속하는 도구가 아니라 판단 자료를 모아 주는 도구이고, §5.3·§6.4 채점으로 쓸모를 계속 검증한다.
