## 1. 목표

국회회의록 사이트(https://record.assembly.go.kr/assembly/)에 올라오는 **제21대·제22대 국회의 모든 회의록 PDF**를 구글 드라이브에 저장하고, 이후 **매일 오전 9시** 새로 올라오거나 임시본에서 확정본으로 바뀐 회의록만 추가로 받는다.

### 범위

- 대수: 제21대(2020.05.30~2024.05.29), 제22대(2024.05.30~)
- 회의구분 6종 전부: 국회본회의(1), 상임위원회(2), 특별위원회(3), 예산결산특별위원회(4), 국정감사(5), 국정조사(6)
- 위원회: 각 회의구분 아래 있는 모든 위원회. 위원회 목록은 사이트에서 매 실행 시 읽어 오므로 신설·개칭에 자동 대응
- 파일 형식: PDF만
- 실행 위치: 1단계는 이 PC. 서버 이전은 별도 작업

### 범위 밖

- HWP 다운로드, 부록·영상회의록, 발언자별 추출
- Google Drive API 업로드 (서버 이전 시 추가)
- 텔레그램 알림, 요약 생성

## 2. 사이트 구조 (조사 결과, 2026-09-09 확인)

모든 요청은 `User-Agent`를 일반 브라우저 값으로, `Referer`를 사이트 내부 주소로 보낸다. 로그인·API 키 불필요.

### 2.1 위원회 목록 (HTML GET)

`GET /assembly/mnts/total/{대수}.do?class_id_sch={회의구분}&cmit_chk=all`

응답 HTML 안의 `<a class="tit cmit" data-cmit="XX" data-th="22" data-class="2">위원회명</a>` 노드에서 위원회 코드와 이름을 읽는다. 회의구분 1(본회의)과 4(예결위)는 위원회 노드 대신 `<a class="tit sess" data-sess="439">` 회기 노드가 바로 나온다.

주의: 위원회 코드(`AA`, `AS` 등)는 **대수·회의구분별로 다르다**. 예: 22대 과방위는 상임위(2)에서 `AF`, 국정감사(5)에서 `AG`. 절대 하드코딩하지 않고 매번 트리에서 읽는다.

### 2.2 회기 목록 (AJAX POST)

`POST /assembly/mnts/async/sessCmit.do`
필드: `th_sch`, `class_id_sch`, `cmit_id_sch`(위원회 코드), `cmit_chk=all`

응답 HTML의 `<a class="tit ..." data-sess="438">제438회 (...)</a>`에서 회기 번호를 읽는다. 국정감사(5)는 회기 대신 연도(`2025`)가 온다.

### 2.3 회의 목록 (AJAX POST)

| 회의구분 | 주소 | 필드 |
|---|---|---|
| 본회의(1) | `/assembly/mnts/async/sess.do` | `th_sch, class_id_sch=1, sess_sch, chk=all` |
| 상임위(2)·특위(3)·국조(6) | `/assembly/mnts/async/cmit.do` | `th_sch, class_id_sch, sess_sch, cmit_cd_sch, cmit_chk=all` |
| 예결위(4) | `/assembly/mnts/async/cmit.do` | `th_sch, class_id_sch=4, sess_sch, cmit_cd_sch=G1, cmit_chk=all` |
| 국정감사(5) | `/assembly/mnts/async/cmit.do` | `th_sch, class_id_sch=5, conf_year, cmit_cd_sch, cmit_chk=all` |

응답 HTML의 `<li>` 하나가 회의 하나. 읽을 값:

- `<a class="tit ord_num" data-id="57155" title="재정경제기획위원회 제1차 (2026. 08. 20.)">` → 회의록 ID, 제목
- `<span class="temp">[임시]</span>` 존재 여부 → 임시회의록 여부
- `href="/assembly/viewer/minutes/download/pdf.do?id=57155"` 존재 여부 → PDF 유무

### 2.4 PDF 다운로드

`GET /assembly/viewer/minutes/download/pdf.do?id={회의록ID}`
(`Referer: https://record.assembly.go.kr/assembly/viewer/minutes/xml.do?id={ID}&type=view` 필요. 없으면 400)

응답 헤더 `Content-Disposition: attachment; filename="<URL인코딩된 파일명>"`을 디코딩해 파일명으로 쓴다.
예: `제22대국회 제438회(임시회) 제1차 재정경제기획위원회(전체회의) (2026.08.20.).pdf`

크기: 위원회 회의록 1~2MB, 본회의 5~8MB. 22대 2,256건 ≈ 4GB, 21대 ≈ 7GB 예상. 드라이브 여유 32.8GB (2026-09-09 기준).

## 4. 프로그램 구성

`G:\내 드라이브\dev\자동화\01_국회회의록\`

| 파일 | 역할 |
|---|---|
| `collect_minutes.py` | 실행 진입점. `--daily`(기본) / `--backfill 21,22` / `--dry-run` / `--limit N` |
| `config.yaml` | 저장 루트 경로, 대상 대수, 요청 간격(초), 최근 확인 회기 수, 재시도 횟수 |
| `README.md` | 실행 방법, 폴더 구조, 문제 해결 |
| `requirements.txt` | requests, beautifulsoup4, lxml, pyyaml |

`collect_minutes.py` 내부는 세 층으로 나눈다.

1. **site 층** (`RecordSite` 클래스): 사이트 요청만 담당. `committees(th, cls)`, `sessions(th, cls, code)`, `meetings(th, cls, code, sess_or_year)`, `download_pdf(id) -> (filename, bytes)`. 요청 간격·재시도·세션 쿠키를 여기서 처리.
2. **catalog 층**: site 층을 조합해 "받아야 할 회의록 목록"(`MinutesEntry`: id, 대수, 회의구분, 위원회명, 회기/연도, 제목, 임시여부)을 만든다. `iter_all(th)`와 `iter_recent(th, n_sessions)` 두 진입점.
3. **store 층** (`LocalDriveStore` 클래스): 경로 결정, 파일 쓰기, manifest 읽기·쓰기, 로그 append. 서버 이전 시 이 클래스만 `DriveApiStore`로 교체한다.

## 5. 동작 흐름

### 5.1 전체 수집 `--backfill 21,22`

```
for 대수 in [22, 21]:
  for 회의구분 in [1..6]:
    위원회 목록 (구분 1·4는 단일)
    for 위원회:
      회기(또는 연도) 목록
      for 회기:
        회의 목록
        for 회의:
          manifest에 같은 id가 있고 임시여부가 같으면 skip
          PDF 없으면 manifest에 status=no_pdf 기록 후 skip
          다운로드 → 저장 → manifest 갱신 → 로그
```

- 22대를 먼저, 21대를 나중에. 중단 후 재실행하면 manifest 기준으로 이어서 받는다.
- 요청 간격 기본 1.0초. 다운로드 실패는 3회 재시도(지수 백오프), 그래도 실패하면 status=error로 기록하고 계속 진행.

### 5.2 매일 수집 `--daily`

- 대상 대수는 config의 `current_th`(22) 하나.
- **Open API 키가 있을 때 (2026-09-09 추가, 기본 구성):**
  - 본회의·상임위·특위·예결위 목록은 열린국회정보 Open API로 받는다. 최근 `api_months`(기본 2)개월을 `CONF_DATE=YYYY-MM` 접두 검색으로 조회. API 주소: 본회의 `nzbyfwhwaoanttzje`, 위원회 `ncwgseseafwbuheph` (필수 인자 `DAE_NUM`, `CONF_DATE`; 브라우저 User-Agent 필요; 응답은 안건 단위라 `CONFER_NUM`으로 중복 제거; `CONFER_NUM` = 사이트 회의록 ID).
  - 국정감사·국정조사는 API가 데이터를 주지 않으므로(2024-03 등록된 `VCONF*` API군은 모두 "해당 데이터 없음") 사이트 트리를 최근 회기/연도 기준으로 읽는다.
  - API는 임시/확정 여부를 주지 않는다. API로 처음 받은 회의록은 임시로 기록하고, manifest에 임시로 남아 있는 항목은 해당 (위원회, 회기)만 사이트에서 다시 읽어 확정본이면 교체한다.
- **키가 없을 때:** 회의구분 1·2·3·4·6은 최신 회기 2개, 국정감사(5)는 최근 연도 2개를 사이트에서 읽는다.
- 새 id이거나, manifest에는 임시(`temp=true`)인데 사이트에서 확정으로 확인된 것만 받는다. 확정본은 같은 파일명으로 덮어쓴다.
- 실행 시간 목표: 5분 이내.

### 5.3 manifest (`_manifest.json`)

```json
{
  "57155": {
    "th": 22, "cls": 2, "committee": "재정경제기획위원회", "sess": "438",
    "title": "재정경제기획위원회 제1차 (2026. 08. 20.)",
    "temp": true, "status": "ok",
    "path": "제22대/상임위원회/재정경제기획위원회/제22대국회 제438회(임시회) 제1차 재정경제기획위원회(전체회의) (2026.08.20.).pdf",
    "size": 1187888, "downloaded_at": "2026-09-09T11:30:00+09:00"
  }
}
```

`status`: `ok` / `no_pdf` / `error`. 원자적 저장(임시 파일에 쓰고 rename)으로 중단 시 손상 방지. 50건마다 저장.

## 6. 오류 처리

| 상황 | 처리 |
|---|---|
| HTTP 오류·타임아웃 | 3회 재시도 후 error 기록, 다음 건 진행 |
| PDF 링크 없음 | no_pdf 기록, 로그에 남김 |
| 응답이 PDF가 아님(HTML 오류 페이지) | 매직바이트 `%PDF` 확인, 아니면 error |
| 파일명 없음 | `제{대수}대_{회의구분}_{위원회}_{id}.pdf`로 대체 |
| 디스크 여유 2GB 미만 | 즉시 중단, 로그에 경고 |
| 트리 구조 변경으로 파싱 결과 0건 | 경고 로그. 다른 구분은 계속 진행 |

## 7. 실행과 예약

- 수동: `python collect_minutes.py --daily`
- Windows 작업 스케줄러: 매일 09:00 실행 등록은 사용자 요청 시 별도 명령으로 제공(PC가 켜져 있을 때만 동작).
- 서버 이전(추후): store 층을 Google Drive API 구현으로 교체하고, 서버 cron 또는 n8n에서 09:00 실행.

## 8. 검증 계획

1. `--dry-run --backfill 22 --limit 20`: 다운로드 없이 목록·경로만 출력해 폴더 구조와 파일명 확인.
2. 재경위 최근 회기 1개 실제 다운로드 → 드라이브에서 파일 열어 확인.
3. `--daily` 두 번 연속 실행 → 두 번째는 0건이어야 함(중복 방지 확인).
4. `--backfill 22` 전체 실행(1시간 이상), 이어서 `--backfill 21`.
5. manifest 건수와 사이트 표시 건수(22대 2,256건) 비교.
