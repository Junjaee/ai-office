# 카드문자 전달 앱 — 설계 (2026-09-22)

배경: 카드 승인 문자를 지메일로 넘겨 주던 MacroDroid 가 유료로 바뀌어 9/13 부터 전달이 멈췄다(누락분은 손으로 넣음). 사용자 결정(2026-09-22): **우리가 직접 만든 안드로이드 앱을 APK 로 설치**해 MacroDroid 자리를 대신하고, **Cloudflare 가 1분마다 지메일을 확인해 새 카드 문자가 있으면 가계부를 바로 깨운다**(상임위 메일과 같은 방식).

## 1. 한 줄

폰(갤럭시 S25)에 깐 앱이 "승인·취소"가 든 카드 문자를 **구글 계정 권한(메일 넣기 전용)** 으로 지메일에 `[카드SMS]` 메일로 넣고, Worker 가 1분마다 그 메일을 확인해 가계부(`ledger.yml`)를 깨운다. 가계부 파이썬·시트·6시간 예약은 **바뀌지 않는다**.

```
[전]  카드문자 → MacroDroid ─▶ 지메일 [카드SMS] ─▶ 가계부(6시간마다) ─▶ 시트
[후]  카드문자 → 카드문자 전달 앱 ─▶ 지메일 [카드SMS] ─▶ Worker 1분 감시 → 가계부 즉시 ─▶ 시트
                                                    └─▶ 가계부(6시간마다, 안전망)
```

## 3. 앱 (`android/cardsms/`)

Kotlin, AppCompat + XML 화면 하나, 의존성은 `appcompat` · `work-runtime-ktx` 뿐(HTTP 는 `HttpURLConnection`, JSON 은 `org.json`). 권한은 `RECEIVE_SMS` · `INTERNET` 두 개.

| 단위 | 하는 일 | 순수 함수(테스트 대상) |
|---|---|---|
| `SmsReceiver` | 매니페스트에 등록된 `SMS_RECEIVED` 수신기. 여러 조각(PDU)을 한 본문으로 합치고, 골라내기를 통과하면 `ForwardWorker` 를 예약 | `joinParts`, `shouldForward(body, keywords)` |
| `ForwardWorker` | 액세스 토큰 갱신 → `messages.insert` → 결과를 기록. 실패(네트워크·5xx)면 재시도, 4xx(토큰 오류)면 실패로 기록 | `buildRawMessage(subject, body, now)`(RFC822 → base64url), `classifyFailure(status)` |
| `GmailClient` | 토큰 갱신(`oauth2.googleapis.com/token`)과 insert 호출. 값은 로그에 남기지 않는다 | — |
| `Settings` | SharedPreferences(앱 전용 저장소): client_id · client_secret · refresh_token · 제목 · 키워드 | `parseSettingsJson` |
| `ForwardLog` | 최근 20건(시각·본문 앞 20자·성공/실패 사유). 본문 전체는 저장하지 않는다 | — |
| `MainActivity` | 설정 파일 불러오기 · 키워드 편집 · 저장 · 테스트 전송 · 최근 기록 · 권한/배터리 상태와 설정 바로가기 | — |

- **테스트 전송**은 제목을 `[카드문자앱 테스트]` 로 보낸다(가계부 검색어에 안 걸리게).
- 배터리 최적화 제외 버튼은 `ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` 를 연다(사이드로드 앱은 플레이스토어 정책 밖이라 허용됨). 삼성 "딥 슬립 앱"에 들어가면 멈추므로 README 에 확인 방법을 적는다.
- 설정 파일 형식:
  ```json
  { "client_id": "…", "client_secret": "…", "refresh_token": "…",
    "subject": "[카드SMS]", "keywords": ["승인", "취소"] }
  ```

## 4. Worker 감시 (`worker/gmail.ts` · `schedule.ts` · `index.ts`)

상임위 메일과 같은 모양으로 **한 줄 더**. 전제: **가계부는 파싱 못 한 메일에도 라벨을 붙인다**(`run_ledger.py`, 2026-09-22) — 그래야 감시가 같은 메일로 계속 깨우지 않는다.

- `gmail.ts`: `LEDGER_WATCH_QUERY`, `LEDGER_COOLDOWN_MS`(10분), `shouldWake(count, lastMs, nowMs, cooldown)` 순수 함수.
- `schedule.ts`: `LEDGER_WATCH_JOB = { workflow: "ledger.yml", cron: "", note: "가계부 — 새 카드 문자가 오면(1분마다 확인)" }`.
- `index.ts`: `hasNewCommitteeMail` 을 `hasNewMail(env, query, lastMs, nowMs)` 로 일반화하고 `lastLedgerDispatchMs` 를 따로 기억. 같은 분에 6시간 예약과 감시가 둘 다 `ledger.yml` 이면 **하나만** 깨운다(`dueJobs` 의 중복 제거와 같은 규칙).
- 가계부 워크플로는 `concurrency: group: ledger` 라 겹쳐 깨워도 순서대로 돈다. 두 번째 실행은 "신규 0건"으로 끝난다.
- 토큰이 없거나 확인에 실패하면 false(예약 처리는 그대로).

## 5. 빌드·서명·전달 (`.github/workflows/cardsms-app.yml`)

1. `workflow_dispatch` 만. ubuntu-latest, JDK 17(temurin), `gradle/actions/setup-gradle`(Gradle 8.9, 저장소에 wrapper jar 를 두지 않는다), `android-actions/setup-android`(platform 34, build-tools 34.0.0).
2. GitHub Secrets `CARDSMS_KEYSTORE_B64` · `CARDSMS_KEYSTORE_PASSWORD` · `CARDSMS_KEY_ALIAS` · `CARDSMS_KEY_PASSWORD` 로 서명. 비밀값이 없으면(로컬 빌드) 서명 없이 debug 로 빌드된다.
3. `gradle test assembleRelease` → 산출물 `cardsms-apk`(30일 보관).
4. 로컬에서 `gh run download` 로 받아 `ai-home/01_가계부/카드문자전달.apk` 에 복사(드라이브가 폰으로 올린다).
5. 업데이트도 같은 절차. 같은 서명키라 폰에서 "업데이트 설치"로 덮인다.

## 6. 토큰 발급 (PC 에서 1회)

`make_combined_token.py` 와 같은 방식으로 **`gmail.insert` 만** 요청하는 스크립트를 돌린다. 브라우저가 열리면 사용자가 계정 선택 → "확인되지 않은 앱" 고급 → 이동 → 허용. 결과를 `ai-home/01_가계부/카드문자전달-설정.json` 에 쓴다(채팅·커밋 금지). 발급 직후 파이썬으로 `[카드문자앱 테스트]` 메일 1통을 넣어 권한을 확인하고 지운다.
만약 구글이 `gmail.insert` 동의를 막으면(제한 범위 심사) 가계부와 같은 `gmail.modify` 로 대체한다(권한이 넓어지는 것만 다르다).

## 7. 보안·사생활

- 앱 밖으로 나가는 문자는 키워드를 통과한 것뿐. 본문은 기록에 남기지 않는다(앞 20자만).
- 폰이 가진 토큰은 메일을 **넣기만** 할 수 있다. 분실 시 최악은 가짜 카드 메일이 들어오는 것.
- 서명키·설정 json 은 개인 폴더(`ai-home/`, gitignore)에만. GitHub Secrets 값은 채팅에 내보내지 않는다.
- Worker 는 건수만 본다(기존과 같음).

## 8. 테스트

- Worker: `tests/gmail.test.mjs` 에 `LEDGER_WATCH_QUERY`·`shouldWake`, `tests/schedule.test.mjs` 에 `LEDGER_WATCH_JOB`. `npm test` · `tsc` 통과.
- 앱(JVM 단위 테스트, 빌드 때 실행): `shouldForward`(승인/취소/일반문자), `joinParts`(조각 합치기), `buildRawMessage`(제목·UTF-8 본문·base64url), `parseSettingsJson`(필수값 누락).
- 실제: ① 토큰 발급 직후 파이썬으로 insert 1통 확인 → ② Worker 배포 뒤 `[카드SMS]` 시험 메일을 넣어 1~2분 안에 가계부가 깨는지(`gh run list`) 확인 → ③ 폰 앱 "테스트 전송" → ④ 실제 결제 1건이 시트에 들어오는지.

## 9. 사용자가 직접 하는 일

1. 토큰 발급 때 브라우저에서 **허용 1회**.
2. 폰: 드라이브 앱에서 `카드문자전달.apk` 터치 → "출처를 알 수 없는 앱 허용" → 설치 → 앱에서 **설정 파일 불러오기**(`카드문자전달-설정.json`) → 문자 권한 허용 → **배터리 최적화 제외** → 테스트 전송.

## 10. 하지 않는 것

- 카톡 알림톡·앱 푸시(문자 아님)는 잡지 않는다. 지금 카드 알림은 전부 `[Web발신]` 문자.
- 앱에서 시트에 직접 쓰지 않는다(날짜순 삽입 규칙은 파이썬 한 곳에만).
- 중복 방지(전송 시간초과 직후 재시도로 같은 문자가 두 번 들어가는 드문 경우)는 이번엔 두지 않는다. 생기면 파이썬 쪽에 넣는다.
- 알림(실패 푸시)은 없다. 앱 화면의 최근 기록으로 본다.

## 12. 변경 (2026-09-23, 사용자 결정) — 설정은 앱 화면에서, 발신번호 기준

- **설정 파일(json) 폐지.** 앱 화면에서 전부: [구글 계정 연결] 버튼(브라우저 동의 1회, 연결된 이메일 표시), 발신번호 목록(입력 + [추가], 항목마다 [삭제], 메모 가능), "위 번호에서 온 문자는 전부 전송" 체크(기본 켬), 체크를 끄면 키워드.
- **골라내기 = 발신번호 기준.** 등록 번호에서 온 문자만 보낸다(번호가 없으면 아무것도 안 보냄). 하이픈·공백·`+82` 는 같은 번호로 본다(숫자만 남겨 끝자리 7자리 이상 매칭). 키워드는 보조.
- **구글 연결 방식**: 설치형 앱 OAuth 클라이언트 + PKCE + 폰 안의 loopback(`http://127.0.0.1:포트/`) 서버로 코드 수신 → 토큰 교환 → 리프레시 토큰을 앱 저장소에. 권한 `gmail.insert openid email`. 연결 완료 페이지가 `cardsms://` 로 앱을 다시 띄운다(`launchMode=singleTop`). 클라이언트 id·secret 은 저장소에 없고 빌드 때 `BuildConfig` 로 주입(CI Secrets `CARDSMS_GOOGLE_CLIENT_ID/SECRET`, 로컬은 `scripts/gradle.sh` 가 개인 폴더 `client_secret.json` 에서 읽음).
- `android/cardsms/tools/make_token.py` 와 `카드문자전달-설정.json` 은 더 쓰지 않는다(삭제).
- 기록에 발신번호를 남겨 새 카드 번호를 알아낼 수 있게 한다.
- 설치 장벽(2026-09-22~23 실측): 드라이브 앱은 APK "다운로드할 수 없음", 지메일은 APK 첨부를 "바이러스"로 차단, Play 프로텍트는 문자 권한 앱의 스토어 밖 설치를 차단 → README 에 우회(크롬 직접 링크·Claude 첨부·USB·텔레그램, Play 프로텍트 검사 끄기·adb) 정리.

## 13. 변경 (2026-09-23 저녁, 사용자 결정) — 구글 계정은 다시 설정 파일로

- 폰에서 구글 로그인하는 두 방식(폰 안 임시 서버 loopback → `ERR_CONNECTION_REFUSED` 두 번; 안드로이드 OAuth 클라이언트 + 커스텀 스킴 → 구글 콘솔 등록이 필요해 복잡)을 버리고, **PC 에서 `make_token.py` 로 만든 `카드문자전달-설정.json` 을 앱에서 불러오는** 처음 방식으로 돌아간다. 이미 만든 파일(넣기 전용 토큰)을 그대로 쓴다.
- 앱 화면의 나머지(발신번호 목록 추가/삭제·전체/키워드 전송·기록에 발신번호·버전 표시)는 12절 그대로. 버튼은 [설정 파일 불러오기]/[설정 파일 지우기].
- 빌드 주입값·매니페스트 스킴·`GoogleOAuth`·`GoogleConnectFlow` 삭제. CI Secrets `CARDSMS_GOOGLE_*` 3개는 더 쓰지 않는다.
