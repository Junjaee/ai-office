# 회의 발언 요약 알림 설계 (2026-11-05)

재경위·예결위 회의가 생중계되는 동안 국회 인터넷의사중계의 자막을 받아, 위원 한 사람의 질의가 끝날 때마다 발언을 요약하고 **10명씩 묶어** 530호 알림 봇(텔레그램)으로 보내는 자동화. **이준석 위원 발언은 항상 따로** 보낸다.

사전 조사: `docs/superpowers/specs/2026-11-05-회의-발언-요약-알림-design.md`(이 문서) 작성 전에 확인한 사실은 1절과 4절에 적었다. 자막 수신 시험 코드는 `.github/workflows/diag.yml` 의 `webcast-live` 잡.

## 1. 사용자 결정 (2026-11-05 대화)

| 항목 | 결정 |
|---|---|
| 대상 회의 | 재경위(xcode 65)·예결위(xcode 21) 생중계. 그 채널에서 방송되는 것은 전부(전체회의·국정감사·종합정책질의 등) |
| 시점 | **회의가 진행되는 동안** 실시간. 회의록이 올라오길 기다리지 않는다 |
| 묶음 | 위원 **10명 단위**로 한 번에 올린다 |
| 도는 날 | **이준석 위원이 질의하는 날만**. 예결위 종합정책질의는 이틀인데 그중 하루만 질의하므로, 질의순서 표에 이름이 있는 날만 돈다 |
| 이준석 위원 | **항상 따로** 올린다. 묶음에 넣지 않는다 |
| 이준석 앞의 자투리 | 이준석 위원 차례가 되면 그때까지 요약이 끝난 것은 10명이 안 돼도 **바로** 올린다. 요약이 아직 안 끝난 것(바로 앞 사람)은 **이준석 발언 다음에** 따로 올린다 — 규칙이 아니라 "준비된 순서대로" |
| 수집 | 국회 인터넷의사중계 자막을 **직접** 받는다. seoul-raphael.github.io/assembly-minutes 는 같은 자막을 브라우저에서 보여 주는 개인 사이트라 거치지 않는다 |
| 요약 AI | 새로 돈 들이지 않는다. 기존 공통 모듈 `automations/common/llm.py`(Claude 구독 CLI → 안 되면 Gemini 무료 등급) |
| 받는 곳 | 530호 알림 봇(`NOTICE_530_BOT_TOKEN`/`NOTICE_530_CHAT_ID`, 단체방 포함 — 쉼표로 여러 방) |
| 실행 위치 | **GitHub 서버**. 2026-11-05 ubuntu 실행기에서 생중계 목록·채널 정보·자막 서버 접속 전부 확인됨(해외 차단 없음). PC 를 켜 둘 필요 없다 |
| 질의 순서 | **상임위 메일 자동화(`mail`)가 받는 행정실 메일의 "질의순서" 첨부(HWP)에서 가져온다.** 재경위는 `fec@assembly.go.kr`, 예결위는 `budget@assembly.go.kr` 에서 회의 전날 밤~당일 아침에 온다. 예결위 종합정책질의는 이틀인데 **이준석 위원은 그중 하루만** 질의한다 — 그 날은 질의순서 표에 이름이 있는 날이다 |
| 회의 일정 | **구글 캘린더 "530호 일정 (비공개)"에서 읽는다**(주말 일정 자동화가 이미 읽는 그 캘린더). 국회 사이트를 하루 종일 두드리지 않고, 캘린더에 재경위·예결위 일정이 있는 시간대에만 방송 여부를 본다. 카드의 "다음 실행"도 캘린더의 다음 회의로 보여 준다 |

## 2. 범위

**만드는 것**

- 자동화 `speech`(국회 사무실, 부서 `qa` 상임위 메일팀 — 재경위·예결위를 보는 팀이라 같은 곳에 둔다). 카드 이름 "회의 발언 요약". 직원 3명: `listen` 자막 수신 · `summarize` 발언 요약 · `notify` 알림 전송.
- 파이썬 `automations/speech/`: 자막 수신(두 종류) → 위원별 발언 자르기 → 요약 → 묶음 전송.
- 워크플로 `.github/workflows/speech.yml`: 입력 `xcode`. 한 번 켜지면 방송이 끝날 때까지(최대 6시간) 돈다.
- Worker: 1분마다 생중계 목록을 보고 재경위·예결위가 **방송 중이면** 워크플로를 깨운다(`worker/webcast.ts`). 실행 중 상태 저장용 작은 API(`/api/speech/state`, R2).

**만들지 않는 것**

- 본회의·다른 위원회. 설정 목록에 채널을 더하면 되게만 만든다.
- 영상·음성 처리. 자막만 쓴다.
- 발언 원문 보관·검색 화면. 원문은 회의 중 이어 받기용으로만 R2 에 두고, 공개 저장소에는 **건수만** 남긴다.
- 사실 확인·논평. 요약은 "누가 무엇을 물었고 어떤 답이 나왔나"까지.
- 회의가 끝난 뒤 공식 회의록으로 보정하기(나중 과제).

## 3. 흐름

```
Worker (1분마다) — 국회 사이트는 부르지 않는다. 캘린더와 GitHub·R2 만 본다.
  구글 캘린더(530호 일정) → 지금이 재경위/예결위 일정의 시간대인가? (시작 10분 전 ~ 끝 3시간 뒤)
  → 그 시간대이고, 그 xcode 의 speech.yml 이 돌고 있지 않고,
    R2 에 오늘 그 xcode 의 "건너뜀"/"끝남" 표시가 없고, 마지막 깨움 뒤 10분이 지났으면
  → workflow_dispatch(xcode, window_end)

speech.yml (ubuntu, 최대 6시간)
  0 질의순서 HWP(지메일) → 오늘 표에 이준석 위원이 없으면
      R2 에 "건너뜀" 표시(speech/skip/<날짜>-<xcode>)를 쓰고 바로 끝낸다(1분 안, 상태는 끝남 · "오늘 질의 없음")
  1 방송 대기: live_list.asp 를 60초마다 → 그 채널 xstat=1 이 될 때까지(window_end 까지). 정회 중에도 끝내지 않고 기다린다.
  2 채널 정보(live_play.asp) → 자막 서버 주소·회의 이름·xcgcd / 위원 명단(live_map.asp)
  3 상태 복원(/api/speech/state?key=<xcgcd>) → 이미 보낸 묶음·순번·받다 만 발언
  4 자막 수신 루프
      줄이 올 때마다 → 호명 판정 → 발언 구간 나누기
      구간이 닫히면 → 요약(백그라운드 스레드) → 준비 큐
      준비 큐가 10명 → 묶음 전송
      이준석 호명 → 준비 큐 즉시 전송(10명 미만이어도)
      이준석 구간 닫힘 → 단독 전송 → 그 사이 준비된 것 전송
      30초마다 상태 저장(/api/speech/state)
  5 끝 조건(산회 자막 · window_end 도달) → 남은 것 전부 전송 → R2 "끝남" 표시(speech/done/<날짜>-<xcode>) → 상태 보고(report) → 종료
      방송이 잠깐 끊긴 것(정회·서버 끊김)은 끝이 아니다 — 1 로 돌아가 다시 기다린다.
```

같은 워크플로가 재경위·예결위로 **동시에** 돌 수 있다(`concurrency: speech-<xcode>`). 6시간을 넘겨 끊기면 "끝남" 표시가 없으므로 다음 분에 Worker 가 다시 깨우고, 상태 복원으로 이어 간다(끊긴 몇 초의 자막은 잃는다 — 감수).

**왜 Worker 가 국회 사이트를 안 보나(검토자 질문에 대한 결정, 내 판단)**: ① Cloudflare 엣지 IP 에서 webcast 가 열리는지는 확인된 바 없고(GitHub·이 PC 만 확인), 막혀 있으면 구조를 바꿔야 한다 ② "이준석 위원이 질의하는 날인지"는 HWP 표를 읽어야 알 수 있어 Worker(TypeScript)가 판정할 수 없다. 둘 다 워크플로 쪽으로 옮기면 Worker 는 캘린더·GitHub·R2 만 보면 되고, 국회 사이트 접속은 이미 확인된 GitHub 서버에서만 일어난다. 대신 이준석 위원이 없는 날에도 **1분짜리 실행 1건**이 이력에 남는다 — 하루 1,440건이 아니라 회의당 1건이므로 받아들인다. 회의 중 Worker 가 1분마다 하는 일은 캘린더(하루 1회 캐시)·GitHub 실행 목록 1회·R2 head 1회뿐이다.

## 4. 자막 수신 (조사 결과, 2026-11-05)

채널 상세 `GET https://assembly.webcast.go.kr/main/service/live_play.asp?xcode=&xcgcd=` 의 `xsami` 가 자막 서버다. **두 종류**이고 회의마다 어느 쪽이 올지 다르므로 둘 다 받는다(플레이어 `openos_util.js` 의 `smi_on()` 과 같은 분기).

| 구분 | 주소 모양 | 규격 | 내용 |
|---|---|---|---|
| 속기 자막 | `wss://smi(-hy\|-dw)N.webcast.go.kr/<xcode>` | socket.io **EIO=3**(옛 규격 — `python-socketio<5`, `python-engineio<4`), 네임스페이스 `/<xcode>`, 이벤트 `receive message` | 글 한 줄(30초에 약 10줄). 2026-11-05 본회의 |
| AI 자막 | 그 밖(예 `wss://smiai….:8091/aistt/<채널>`) | 일반 WebSocket, 하위 프로토콜 `echo-protocol`, HLS 는 뒤에 `/hls` | JSON `{segment, transcript, transcripts, final, scd}`. 같은 segment 가 고쳐지며 여러 번 오고 `final && scd` 가 최종. 2026-10-08 재경위 국감 |

둘 다 **화자 이름은 없다.** 요청 헤더 `Origin: https://assembly.webcast.go.kr`, `User-Agent` 는 브라우저 것.

수신 루프는 끊기면 10초 뒤 다시 붙고, 그래도 안 되면 채널 상태(`live_list.asp`)를 봐서 방송이 끝난 것이면 종료한다.

## 4-2. 질의 순서 읽기 (행정실 메일의 HWP)

행정실이 회의 전에 보내는 질의순서 파일을 읽어 **그날 질의할 위원의 순번·이름·정당**을 얻는다. 2026-11-05 실제 파일로 확인한 것:

- 재경위: `질의순서(261103)_….hwp` — 표 1개, 두 단(순번·질의위원·비고 ×2). 셀은 `1 | 김남준 | 위원 | 더불어민주당`.
- 예결위: `2027_예산안_질의순서(전체)_261105_….hwp` — 제목 줄 `<종합정책질의>-2일차 2026년 11월 5일(목)` 뒤에 표(순번·위원명·교섭단체·지역구·비고). 이준석 13번(사용자 예시와 같다).
- HWP 5.0(OLE) 파일. `pyhwp` 의 글자 변환(`hwp5txt`)은 **표 안을 건너뛰므로** HTML 변환(`hwp5.hwp5html.HTMLTransform().transform_hwp5_to_dir`)을 쓰고 `index.xhtml` 의 `<table>` 을 BeautifulSoup 으로 읽는다. 표마다 줄을 훑어 "숫자 | 이름(2~4자 한글) | …" 꼴의 셀을 순번·이름으로 잡고, 정당은 같은 줄에서 당 이름 목록과 맞는 셀로 정한다. 한 줄에 두 단이 있으면(재경위) 둘 다 잡는다.
- 어디서 받나: 드라이브 수신함(`mail` 이 첨부를 저장하는 `folder_id` 폴더, 그 뒤 `sort` 가 회의 폴더로 옮길 수 있음)이 아니라 **지메일에서 직접** — 회의 날짜 전후 3일 안에 그 위원회 주소에서 온 메일 중 첨부 이름에 `질의순서` 가 든 것을 찾아 가장 최근 것을 받는다(`mail_gmail.download_attachment` 재사용, `GOOGLE_*` 토큰은 이미 Secrets 에 있다). 이유: 드라이브 쪽은 `sort` 가 폴더를 옮기고 같은 이름이 두 개씩 생겨(2026-11-05 확인) 어느 것이 최신인지 가리기 어렵다. "변경·재송부" 메일이 오면 더 최근 것이 자동으로 이긴다.
- 쓰임새 세 가지: ① **호명 판정의 후보 명단**(명단에 있는 이름만, 다음 순번 이름이 나오면 더 확신) ② **묶음 제목의 순번**(표의 순번을 그대로 쓴다 — 보충질의처럼 표 밖 순서가 생기면 그 뒤로 이어 센다) ③ **이준석 위원이 오늘 질의하는지**(표에 이름이 있으면 그날이 "우리 의원 날").
- 못 받으면(메일 없음·HWP 깨짐) 의석 명단(`live_map.asp`)만으로 간다 — 호명은 잡히고 순번은 호명 순서대로 1부터 센다. 상태에 "질의순서 없이 진행"을 남긴다.
- 표 내용(이름·정당)은 공개 저장소·로그에 쓰지 않는다(건수만).

## 5. 위원별 발언 자르기 (사회자 호명 기준)

- **호명 문장**을 정규식으로 잡는다. 대상은 질의순서 표의 이름(없으면 의석 명단 `live_map.asp`)만. 질의순서가 있으면 "다음 순번 이름"이 호명에 나올 때를 가장 확실한 신호로 보고, 순번을 건너뛴 호명(불참·순서 바꿈)도 표에 있는 이름이면 받아들인다. 예: `(다음은|이어서)? ?(.{2,4}) 위원님? ?(질의|질문)(하여|해) ?주시(기|겠)…`, `… 위원님 질의하겠습니다`, `… 위원 질의하십시오`. "존경하는 ○○ 위원님" 같은 동료 언급은 "위원님 질의" 조건으로 걸러진다(2026-10-08 시험에서 확인).
- 호명이 나오면 **앞 위원 구간을 닫고** 새 구간을 연다. 한 구간에는 그 위원의 질의와 장관·기관장의 **답변이 섞여** 있다 — 자막에 화자가 없어 가를 수 없으므로 요약도 "질의 + 주요 답변"으로 한다(내 판단).
- 같은 위원이 보충질의로 다시 나오면 **새 순번**의 구간이다. 이준석 위원도 나올 때마다 따로 보낸다.
- 순번은 회의(xcgcd) 안에서 1부터 센다. 묶음 제목에 "질의 1~10" 처럼 쓴다.
- 구간 닫힘 조건: 다음 호명 · **"○○ 위원님 수고하셨습니다"**(질의 종료 선언, 다음 호명 전 장관 발언·사회자 말 3분이 끼는 걸 막는다) · "정회/휴식/산회" 문장 · 방송 종료 · **호명 없이 25분 경과**(놓친 호명 대비, 내 판단). 25분 규칙으로 닫힌 구간은 "호명 못 잡음" 표시를 달아 묶음에 넣는다 — 조용히 사라지지 않게.
- **호명은 자막 두 줄에 갈려 올 수 있다**(2026-11-05 예결위 실측: `20:34:39 "권한영 위원님 수고하셨습니다 다음은 경기 화성을의"` → `20:34:42 "개혁신당 이준석 위원님 질의하여 주십시오"`, `21:19:30 "다음은 충남 논산 계룡 금산의"` → `21:19:32 "황명선 위원님 질의하여 주십시오"`). 정규식은 한 줄이 아니라 **최근 10초 안의 final 자막을 이어 붙인 글**에 건다.
- 개회 직후 호명 전까지(인사말·안건 상정)는 구간 0 "회의 시작"으로 두고 **보내지 않는다**(내 판단).

## 6. 요약

## 7. 묶음·전송 규칙

준비 큐 = 요약까지 끝난 구간을 순번 순으로 쌓은 것.

1. 준비 큐에 **10개**가 모이면 한 묶음으로 보낸다.
2. **이준석 호명이 들어오면** 준비 큐를 즉시 보낸다(1개라도). 아직 요약 중인 구간(대개 바로 앞 사람)은 큐에 없으므로 남는다.
3. 이준석 구간이 닫혀 요약이 끝나면 **단독** 메시지로 보낸다. 그 뒤 준비 큐에 남은 것(예: 12번)을 "뒤늦게" 표시를 달아 보낸다.
4. 회의가 끝나면(산회·방송 종료) 남은 것을 전부 보낸다.
5. 전송 순서는 메시지 안에서는 순번 순, 메시지끼리는 준비된 순이다. 제목에 순번 범위가 있으므로 뒤바뀌어도 알아볼 수 있다.

예(이준석이 13번): 1~10 묶음 → (이준석 호명) 11 단독 묶음 → 이준석 13 단독 → 12 뒤늦게 → 14~23 묶음 …

**메시지 모양**(위원 한 명 부분은 사용자 예시 2026-11-05, 머리글은 내 판단)

```
📋 재경위 제439회 제5차 전체회의 · 질의 1~10 (1/4)

더불어민주당 오기형
1. 주제 제목
◯ 지적한 사실과 근거 … 했음
◯ 요구·제안 … 요구했음
◯ ○○ 장관은 … 답했음
2. 다음 주제
◯ …

더불어민주당 김남준
1. …
```

```
🔵 개혁신당 이준석 · 질의 13
1. 광역버스 준공영제 신설 노선 축소
◯ …
```

- 텔레그램 한 메시지 4,096자 한도 — 넘으면 **위원 경계**에서 나눠 "(1/4)" 처럼 붙인다. 이 모양은 위원 한 명이 1,500~2,500자라서 **10명 묶음은 실제로 4~6개 메시지로 나뉘어 연달아 간다**(실측: 이준석 25분 구간이 주제 8개 2,300자). 묶음 단위는 그대로 10명(사용자 결정)이고, 나누는 건 전송 쪽에서만 한다.
- 보내기 실패는 `telegram_bot.send_message` 의 재시도(3회)로 버티고, 그래도 실패하면 상태 파일에 남기고 다음 묶음으로 간다. 이미 보낸 묶음은 상태에 기록해 재시작 때 다시 보내지 않는다.

## 10. 검증

- 자르기·묶음 규칙은 **순수 함수**로 두고 `automations/speech/tests/` 에서 검사한다: 호명 정규식(명단 있는 이름만, 동료 언급 제외), 13번 이준석 예시가 7절 순서 그대로 나오는지, 25분 규칙, 4,096자 나누기, 재시작 후 중복 전송 없음.
- `--replay <자막 기록 파일>` 로 저장해 둔 자막을 시간 압축해 흘려 넣어 **네트워크 없이** 전체 흐름을 돌린다. `--dry-run` 은 보내는 대신 **파일**(`--out`)에 쓴다. `--record <파일>` 은 받은 자막을 줄 단위로 그대로 저장한다. 시험용 자막 기록·dry-run 결과는 개인 폴더(`ai-assembly/05_회의발언요약/`)에 두고 저장소에는 넣지 않는다.
- Worker: `tests/` 에 `webcast.ts` 순수 함수 검사(캘린더 일정에서 감시 시간대·채널 고르기, 방송 중 판정, 실행 중 판정, 다음 회의 고르기).

**로그 정책(내 판단, CLAUDE.md 의 "공개 저장소에는 건수만" 규칙을 따름)**: GitHub Actions 로그는 누구나 보므로 자막 줄·호명 판정·요약문·위원 이름을 찍지 않는다. 찍는 것은 건수(받은 줄·구간·요약 성공/실패·보낸 묶음)와 오류 종류뿐. 그래서 `--dry-run`·`--record` 는 **이 PC 에서** 돌린다(PC 에서 자막 접속은 2026-10-08·11-05 확인). 워크플로에는 `dry_run` 입력을 두지 않는다.

**저장된 자막 기록**: 2026-11-05 예결위 종합정책질의 2일차(xcode 21, AI 자막)를 이 PC 에서 통째로 받았다 — `ai-assembly/05_회의발언요약/captions_21_20261105.jsonl`(저장소 밖). 호명 13건 안팎·이준석 위원 구간(20:34~20:55)이 들어 있어 `--replay` 시험 자료로 쓴다. 같은 폴더의 `record_captions.py`·`summarize_segment.py` 는 그날의 시험용 스크립트(버리는 코드)다. 그래서 단계를 나눈다:

1. 코드와 가짜 자막(테스트 안에 적은 문장들)으로 순수 함수 테스트까지 만들고, 위 기록으로 `--replay` 테스트를 통과시킨다(호명 정규식·"수고하셨습니다"·정회/산회 문장). Worker 는 `/api/speech/next` 를 먼저 배포해 **캘린더 권한을 확인**한다(8절).
2. Worker 깨우기와 워크플로를 `notify_target: preview` 로 배포한다 — 다음 재경위·예결위 생중계가 **사용자 개인 대화방**으로 온다. 서버 쪽 동작(상태 저장·복원·동시 실행·6시간 이어가기)과 요약 품질을 여기서 본다. 같은 회의를 이 PC 에서 `--record` 로도 받아 두면 속기 자막(socket.io) 쪽 기록도 생긴다.
3. 사용자가 "됐다" 하면 `notify_target: group` 으로 바꿔 커밋한다. 첫 단체방 전송 회의는 사용자가 결과를 지켜본다.

"끝났다"고 할 수 있는 때는 3단계 뒤다.

**이 PC 에서 시험할 때 알아둘 것(2026-11-05 실측)**: PC 사용자 환경변수의 `NOTICE_530_CHAT_ID` 는 **옛 값(사용자 개인 대화방)** 이고 `TELEGRAM_BOT_TOKEN` 은 캘린더 봇(@junjae_bot)이다. 530 알림 봇(@notice530_bot) 토큰과 단체방("530 이준석 의원실") 번호는 `.dev.vars` 에 `NOTICE_530_BOT_TOKEN`·`NOTICE_530_CHAT_ID` 로 넣어 두었으니 시험 전송 전에 `set -a; . ./.dev.vars; set +a` 로 올린다(환경변수보다 나중에 읽혀 덮어쓴다). `claude` 명령줄은 로그인이 풀려 있을 수 있어(`OAuth session expired`) 요약 시험 전에 `claude login` 을 확인한다. `GEMINI_API_KEY` 는 PC 에 없다.

## 12. 알려진 한계

- 화자 구분은 호명에 기대므로 사회자가 이름을 안 부르거나 자막이 이름을 틀리면 구간이 합쳐지거나 엉뚱한 이름이 붙을 수 있다. 25분 규칙과 "호명 못 잡음" 표시로 **빠뜨리지는 않게** 한다.
- 답변과 질의가 한 구간에 섞인다.
- 속기 자막은 사람이 치므로 발언보다 수십 초 늦고, AI 자막은 오타가 있다.
- GitHub 실행기 6시간 한도로 긴 회의는 한 번 끊겼다 이어진다.
