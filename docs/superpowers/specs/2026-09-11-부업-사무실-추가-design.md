# 부업 사무실(/side) 추가 — 설계

날짜: 2026-09-11 · 상태: 승인(사용자, 대화에서)

## 목적

부업(인스타그램 게시글·릴스, 유튜브 쇼츠, 네이버 블로그) 자동화를 담을 세 번째 사무실을 만든다. 이번에는 **사무실 틀(폴더·사이트·문서)만** 만들고, 자동화는 그 뒤 `/new-automation` 스킬로 하나씩 붙인다. 첫 자동화는 인스타그램 게시글.

## 결정 사항 (사용자)

| 항목 | 결정 |
|---|---|
| id / 주소 / 개인 폴더 / 탭 | `side` / `/side` / `ai-side/` / 🎬 부업 |
| 팀 배치 | **팀 = 플랫폼, 자동화 = 계정.** 자동화 하나가 곧 시작 버튼이므로 계정마다 따로 켜고 끌 수 있다 |
| 계정이 늘 때 | 한 팀에 직원(하위 작업) 6명까지. 계정당 직원 2명이면 팀당 계정 3개. 넘으면 같은 플랫폼의 2팀을 연다 |
| 코드 재사용 | 플랫폼당 코드 한 벌(`automations/insta/` 등). 계정별 자동화는 같은 워크플로에 `inputs.account` 만 다르게. 비밀값은 `INSTA_<계정>_...` 처럼 계정별 |
| 팔레트 | 차콜(검정 계열) + 앰버(호박색) 포인트. 골격은 다른 사무실과 같고 강조색만 다름 |
| 기본 사무실 | 국회(`/`) 그대로 |

## 부서 배치 (`app/workspaces/side.ts`)

| 칸(id) | 팀 | 자동화 id 규칙 | 직원(하위 작업) 초안 |
|---|---|---|---|
| research | 📸 인스타 게시글팀 | `insta_<계정>` | 주제 정리 → 글·이미지 제작 → 업로드 |
| brand | 🎞️ 릴스팀 | `reels_<계정>` | 대본 → 영상 제작 → 업로드 |
| strategy1 | 📱 쇼츠팀 | `shorts_<계정>` | 대본 → 영상 제작 → 업로드 |
| qa | ✍️ 블로그팀 | `blog_<계정>` | 주제 정리 → 글 작성 → 발행 |
| 나머지 8칸 | 숨김(`HIDDEN_DEPARTMENTS`) | | |

- 자동화 목록은 **비워 둔다.** 계정 이름이 정해지지 않았고, 규칙상 워크플로가 있는 부서만 그리므로 `/side` 는 첫 자동화가 붙기 전까지 "아직 연결된 자동화가 없어요" 빈 화면이 정상이다.
- 직원 이름은 `/new-automation` 때 확정한다.

## 검증

`bash scripts/npm.sh tsc` 0, `npm.sh test` 통과(side 포함), `npm.sh build` 성공 → push → 사이트 `/side` 탭이 보이고 빈 화면, `/assembly`·`/home` 은 그대로.

## 하지 않는 것

- 자동화 코드, 워크플로, 인스타그램 API 연결 (다음 단계, `/new-automation`)
- 화면 골격·상태 규칙 변경
