# 실시간 호가·체결 녹음 — 설계 초안 (2026-09-28)

사용자 결정: 실시간 호가는 **한국투자증권 KIS Developers** 로 받는다(계좌 개설·앱키 발급은 사용자가 한다). 목적은 "큰 매물이 잡히는 장면"을 자료로 남겨, 일봉으로는 볼 수 없는 세력 신호를 나중에 통계로 검증하는 것이다(`docs/stock/14` 의 후속). 과거 호가·틱은 개인이 무료로 받을 길이 없으므로 **지금부터 매일 녹음해 쌓는다.**

## 2. 하루 흐름 (2026-09-28 현재 1·2·4 구현, 3 의 드라이브 복사·검증·보고는 요약 파일까지만)

1. 08:40 종목 선별(전날 일봉, KRX Open API 또는 네이버 차트) → `picks_YYYY-MM-DD.json`
2. 08:50 접속키 발급 → 웹소켓 연결 → 종목별 호가·체결 등록 → 09:00~15:30 수신·기록(끊기면 지수 백오프로 재연결·재등록, 끊긴 구간을 기록)
3. 15:40 종료 → 검증(메시지 수, 시각 단조성, 체결량 합 vs 일봉 거래량) → Parquet 압축 → 드라이브 복사 → 텔레그램으로 "종목 N개, 메시지 M건, 결손 구간 K개" 한 줄 보고(내용은 건수만)
4. 실패(접속키 발급 실패·연결 불가·디스크 부족)는 텔레그램으로 알린다

## 3. 나중에 이 자료로 검증할 것 (14번 연구의 후속)

- "큰 매물이 갑자기 잡힌다": 1회 체결량이 그 종목 하루 평균 체결량의 N배인 사건, 특정 호가의 잔량이 몇 초 안에 급증·소멸하는 사건 → 그 뒤 며칠 수익률과 폭등 사건 A·B 와의 관계.
- 매물대 소화: 두꺼운 매도 잔량이 체결로 사라지는 속도.
- 표본이 몇 달 쌓여야 통계가 된다. 종목 10~30개 × 하루 → 월 200~600 종목·일. 그 전에는 사례 관찰만.

## 4. 하지 않는 것

자동 주문, 시간외·야간, 파생, 전 종목 수집(한도), 호가 자료의 공개 저장소 커밋(용량·약관).

1. 한국투자증권 계좌 개설(비대면), KIS Developers(apiportal.koreainvestment.com) 가입 → Open API 신청 → **실전투자 앱키·앱시크릿** 발급(시세만 받아도 실전 키가 필요하다).
2. `ai-home/02_주식신호/config.yaml` 에 `kis_app_key`·`kis_app_secret` 두 줄 추가(완료 2026-09-28). 채팅에 붙이지 않는다. 관심 종목은 `kis_watchlist`.
3. 실행 위치(사무실 PC / 클라우드 서버) 결정 → 작업 스케줄러 등록은 사용자 확인 뒤(`install_task.ps1`).
4. 한투에 실시간 등록 한도(3건) 문의(README 문구).

## 6. 2026-09-28 저녁 추가 — 웹소켓 한도(3건)를 우회하는 두 경로 (사용자 승인)

| 경로 | 내용 | 실측 |
|---|---|---|
| **호가 스냅샷**(`kis_snapshot.py`) | REST '주식현재가 호가/예상체결' 조회를 종목 N개에 순서대로 돌려 10단계 호가·잔량·예상체결(71항목)을 저장. 웹소켓 등록 한도와 무관 | 조회 약 1건/초(문서 20건/초, 실측 1.3건/초에서 초과 오류) → 400종목 한 바퀴 약 6분, 전 종목 약 40분. 순간 체결은 못 보지만 어느 가격대에 큰 매물이 걸려 있다 사라졌는지는 남는다 |

- 다음 분석: 1분봉으로 사건 종목 vs 짝 종목의 매물대(가격대별 거래량 분포·상단 매물 비중·매집 흔적)를 t0 이전 10일에서 비교한다(`docs/stock/scripts/kr/` 후속). 표본이 작아(400 vs 373) 방향과 크기만 본다.
- 한도 문의는 웹소켓 3건·REST 1건/초 둘 다 포함(README 문구).

### 6-1. 스냅샷 대상: 시총 범위와 두 층 (2026-09-28 사용자 결정)

- 전 종목(약 2,550)을 0.67건/초로 한 바퀴 돌면 60분이 넘어 호가 스냅샷의 의미가 없다. 사용자 결정: **시총이 너무 커서 세력이 좌지우지할 수 없는 종목은 제외**한다.
- 근거(14번 연구, 2024~2026 사건 A 3,239건): 사건 종목 시총 중앙값 1,154억, 10%~90% 구간 293억~1조 2천억, 5,000억 미만 82%. 5,000억 이상에서 난 사건은 시장 전체 급등(반도체 대형주 등)이라 세력 추적과 무관.
- 기본 범위 **300억 ≤ 시총 < 5,000억**, 거래정지 제외, 주가 500원 이상, 보통주만 → 1,641 종목(2026-09-28 `--plan`).
- 두 층: **A층**(매 바퀴) = 관심 종목 + 세력 흔적 후보 파일 + 범위 안 거래대금 상위로 150개. **B층**(돌려 가며) = 범위 안 나머지(약 1,500)를 바퀴마다 남는 예산(바퀴 300초 ÷ 1.5초 − 150 = 50건)만큼 이어서 조회. A층은 5분마다, B층은 약 2.5시간에 한 번.
- 한도가 풀리면(한투 문의 결과) `--interval` 만 줄인다: 0.5초면 바퀴당 600건 → A층 150 + B층 450, B층 회전 17분. 실시간 '큰 매물 잡히는 장면'은 여전히 웹소켓 3건만 가능하므로, 스냅샷은 5분 단위 잔량 변화(매물벽 생김·사라짐)를 보는 용도다.
