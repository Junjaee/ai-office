## 1. 목표

자동화 전체를 한 화면에서 보는 대시보드. 갓생맘 "AI OFFICE" 템플릿(픽셀 사무실 시뮬레이션, Next.js + vinext + Cloudflare Workers)을 기반으로, **자동화 하나 = 부서 하나**로 배치하고 실제 실행 결과가 부서 상태에 반영되게 한다. Cloudflare Workers 무료 플랜에 GitHub 연동으로 배포한다.

| 항목 | 결정 |

| 범위 | 껍데기 + 실제 상태 연결 |

### 범위 밖

### 3.3 실제 상태 반영 (`app/page.tsx` + `app/status.ts` 신규)

- `app/status.ts`: `/status/index.json`과 각 `/status/<id>.json`을 fetch → `Record<deptId, RealStatus>` 반환. 60초마다 재조회.
- 표시 규칙 (부서 카드와 책상 불빛):
  - `running` → "진행 중"
  - `ok`이고 `updated_at`이 36시간 이내 → "완료"
  - `ok`이지만 36시간 넘음 → "대기" + "오래됨" 배지
  - `ok=false` → **"오류"** (DeptStatus에 추가, 빨간 불빛, CSS 클래스 `error`)
- `ops` 부서: 실제 파일들의 성공 수/전체 수. 하나라도 오류면 "오류".
- `secretary` 부서: 요약 문구 "실제 N개 팀 정상, M개 오류, K개 준비 중".
- 시뮬레이션 캐릭터 동선은 그대로 두되, 실제 상태가 있는 부서 카드에는 "실제" 배지, 없는 부서는 "연출" 배지를 붙인다. 부서 카드를 열면 summary, counts, next_run, log 5줄, 드라이브 링크를 보여 준다.
- 엔진 파일 수정은 `sim.ts`의 `DeptStatus`에 `"오류"` 추가와 `page.tsx`의 `statusClass` 확장으로 최소화한다.

## 4. 배포

- GitHub 저장소 `ai-office`(private). 첫 push 때 Git Credential Manager가 브라우저 로그인을 띄운다 → 사용자가 로그인.
- Cloudflare 대시보드 → Workers & Pages → Create → GitHub 연결 → 저장소 선택 → 빌드 명령 `npm run build`, 배포 명령 `npx wrangler deploy` (템플릿 vinext 구성). 사용자가 계정 가입·연결, 이후 push마다 자동 배포.
- 비밀값 없음(Notion·Discord 미사용). status JSON은 공개돼도 되는 요약만 담는다(회의록 제목·건수). 사이트 주소는 비공개로 관리한다.

## 5. 오류 처리

| 상황 | 처리 |
|---|---|
| status 파일 없음/fetch 실패 | 해당 부서 "연동 대기"로 표시, 콘솔 경고 |
| JSON 형식 오류 | 해당 파일만 무시 |
| git push 실패 | 경고 출력, 자동화는 정상 종료 |
| 로컬 workerd 실행 불가(ARM) | Cloudflare 배포로 확인. `npm run build`만 로컬에서 검증 |
