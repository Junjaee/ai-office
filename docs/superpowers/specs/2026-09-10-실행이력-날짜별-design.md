# 실행 이력 날짜별 보기 — 설계 문서

- 작성일: 2026-09-10
- 사용자 결정: 실행 이력을 날짜별로 골라 보고, **보관 기간 제한 없이 전부** 볼 수 있게 한다. 방법은 **A안(저장소 영구 일지 + 최근 90일 GitHub 실시간 목록 합치기)**. 설계 1/2(기록·가져오기), 2/2(화면·오류·확인) 모두 승인.
- 대상: 사이트의 모든 사무실(`/assembly`, `/home`).

## 1. 지금 구조와 한계

- 화면 맨 아래 "오늘 실행 이력" 표는 `/api/status`(10초/60초 폴링, 서버 15초 캐시)에 섞여 오는 `history` 로 그린다.
- 서버는 GitHub `actions/runs?per_page=30`(최근 30개)을 받아 KST 오늘 시작한 것만 고른다(`worker/run-api.ts` `todayHistory`). 그래서
  1. 지난 날짜를 볼 수 없다.
  2. 하루 실행이 30개를 넘으면 오늘 목록도 잘린다(기사 수집 3시간마다 + 회의록 + 가계부).
- GitHub 는 실행 로그를 90일(설정 최대 400일) 보관한다. 그 뒤 기록은 GitHub 에만 의존하면 볼 수 없다.
- 모든 자동화(`minutes`·`news`·`ledger`)는 실행 끝에 공통 함수 `automations/common/report_status.py` 의 `report()` 로 `public/status/<ws>/<id>.json` 을 커밋한다. 이 파일에 `run_id`·`request_id`·`trigger`·`started_at`·`duration_sec`·`ok`·`summary` 가 있다.

## 2. 결정 요약

| 항목 | 결정 |
|---|---|
| 영구 기록 | 저장소 일지 `history/<ws>/<automation>/<YYYY-MM>.jsonl` (자동화별·월별, KST) |
| 기록 시점 | `report()` 가 상태 파일과 **같은 커밋**에 한 줄 추가 |
| 과거분 | `python automations/common/history_log.py --backfill` 이 git 이력의 상태 파일에서 복원(여러 번 돌려도 중복 없음) |
| 조회 | 새 `GET /api/history?ws=<id>&date=YYYY-MM-DD` = GitHub 날짜 조회 + 그 달 일지 → 실행 번호로 합침 |
| 캐시 | (사무실, 날짜)별. 오늘 30초, 지난 날 10분 |
| 화면 | "실행 이력" + ◀ 날짜(달력) ▶ + 오늘로, "결과" 열 추가, 오늘일 때만 30초마다 새로 고침 |
| `/api/status` | `history` 필드를 뺀다(표는 `/api/history` 만 쓴다) |

## 3. 일지(영구 기록)

### 3.1 위치·형식

- 경로: `history/<ws>/<automation_id>/<YYYY-MM>.jsonl`. 달은 `started_at`(없으면 기록 시각)의 KST 기준.
- `public/` 밖이다 → 사이트 정적 파일로 배포되지 않는다. 서버는 GitHub Contents API(토큰)로만 읽는다.
- 한 줄 = JSON 한 개(UTF-8, 줄바꿈으로 구분). 필드(값이 없으면 키 생략):

| 필드 | 뜻 | 출처 |
|---|---|---|
| `run_id` | GitHub 실행 번호(정수). 이 PC 실행이면 없음 | `GITHUB_RUN_ID` |
| `automation` | 자동화 id | `report()` 인자 |
| `request_id` | 화면에서 누른 요청 번호 | `REQUEST_ID` |
| `trigger` | `manual`·`schedule`·`local` | `GITHUB_EVENT_NAME` |
| `started_at` | 시작 시각(ISO, KST) | `report()` 인자 |
| `duration_sec` | 걸린 시간(초) | `report()` 인자 |
| `ok` | 성공 여부 | `report()` 인자 |
| `summary` | 결과 요약 한 줄(예 "신규 12건, 실패 0건, 18초") | `report()` 인자 |
| `url` | 실행 기록 링크 | `run_url` |
| `recorded_at` | 일지에 쓴 시각(ISO, KST) | 쓰는 순간 |

예시 한 줄:

```json
{"run_id":34448124618,"automation":"news","request_id":"req-20260910160402-link","trigger":"manual","started_at":"2026-09-10T16:04:27+09:00","duration_sec":18,"ok":true,"summary":"신규 12건, 실패 0건, 18초","url":"https://github.com/Junjaee/ai-office/actions/runs/34448124618","recorded_at":"2026-09-10T16:04:45+09:00"}
```

### 3.2 쓰는 곳

- `report_status.py` 에 `append_history(repo, workspace, automation_id, payload)` 를 두고 `report()` 가 `write_status` 바로 뒤에 부른다. `git add` 는 `public/status` 와 `history` 둘 다.
- 실패 보고(`ok: false`)도 똑같이 한 줄 남긴다. dry-run 은 `report()` 를 부르지 않으므로 기록되지 않는다.
- 같은 `run_id` 가 이미 그 파일에 있으면 다시 쓰지 않는다(재시도·재실행 방어).

### 3.3 동시 실행 안전성

- 파일을 자동화별로 나누므로 서로 다른 자동화가 동시에 끝나도 같은 파일을 건드리지 않는다. 현재 `_push_with_retry` 는 충돌 시 `pull --rebase -X theirs` 로 한쪽을 우선하므로, 파일을 같이 쓰면 다른 자동화의 줄이 사라질 수 있다 — 이것을 원천 차단하는 이유다.
- 같은 자동화의 실행은 워크플로 `concurrency: group: <id>` 로 이미 한 줄로 선다.

### 3.4 과거분 복원 (`automations/common/history_log.py --backfill`)

- `git log --reverse -- public/status/<ws>/<id>.json` 의 각 커밋에서 파일 내용을 읽어 3.1 형식으로 바꾼다(`recorded_at` = 그 커밋 파일의 `updated_at`).
- 이미 일지에 있는 `run_id` 는 건너뛴다 → 여러 번 돌려도 같은 결과. 2026-09-10 기준 복원 대상 11건(회의록 5, 기사 2, 가계부 4).
- 결과를 보고한 적 없는 실행(취소 등)은 복원할 수 없다. 최근 90일 안이면 GitHub 목록으로 보인다.

### 3.5 크기

- 한 줄 약 300바이트. 하루 30회면 1년 약 3MB. Contents API 는 raw 로 100MB 까지 읽을 수 있어 월별 파일로 충분하다.

## 4. 서버 `GET /api/history`

### 4.1 요청·응답

- 요청: `ws`(사무실 id), `date`(`YYYY-MM-DD`, KST).
- 거절: `date` 형식이 틀리거나 KST 오늘보다 미래면 `400 {error:"bad_request"}`, 모르는 `ws` 는 `404`.
- 응답:

```json
{
  "date": "2026-09-09", "today": "2026-09-10", "start": "2026-09-10",
  "items": [ { "id": 34448124618, "automationId": "news", "status": "completed", "conclusion": "success",
               "trigger": "manual", "requestId": "req-…", "startedAt": "…", "completedAt": "…",
               "url": "…", "summary": "신규 12건, 실패 0건, 18초" } ],
  "source": "github", "partial": false, "checkedAt": "…"
}
```

- `start` = 일지·실행 기록이 시작된 날(설정 상수 `HISTORY_START = "2026-09-10"`). 화면의 달력 최소값으로 쓴다. `start` 이전 날짜는 400 이 아니라 빈 목록.
- `source`: `github`(GitHub 목록 + 일지), `archive`(GitHub 실패, 일지만 · `partial: true`), `static`(토큰 없음 · 빈 목록).

### 4.2 GitHub 날짜 조회

- KST 하루 `D` → UTC 범위 `(D-1)T15:00:00Z..DT14:59:59Z`. `actions/runs?created=<범위>&per_page=100`, 다음 페이지가 있으면 최대 3페이지.
- `GitHubLike` 에 `listRunsBetween(fromIso, toIso)` 추가. 이 사무실 자동화의 워크플로 파일에 해당하는 실행만 남긴다(기존 `workflowFileOf`).

### 4.3 일지 읽기

- 이 사무실에서 `workflow` 가 있는 자동화마다 `history/<ws>/<id>/<YYYY-MM>.jsonl` 을 Contents API(raw)로 읽는다. 404 는 빈 파일로 본다.
- 줄마다 JSON 파싱, 깨진 줄은 건너뛴다. `started_at`(없으면 `recorded_at`)의 KST 날짜가 `D` 인 줄만.

### 4.4 합치기

- 열쇠: `run_id`. 이 PC 실행(`run_id` 없음)은 `local:<automation>:<started_at>`.
- 둘 다 있으면 상태·결론·시각·링크는 GitHub 값, `summary` 는 일지 값.
- GitHub 에만 있으면 `summary: null`(대기·실행 중·취소 등).
- 일지에만 있으면(90일 지난 날, 이 PC 실행, GitHub 실패) `status: "completed"`, `conclusion: ok ? "success" : "failure"`, `completedAt` = `started_at + duration_sec`, `trigger` 는 일지 값.
- 정렬: `startedAt` 내림차순, 같으면 `id` 내림차순. `HistoryItem.trigger` 에 `"local"` 추가.

### 4.5 캐시·호출량

- `Map<"<ws>/<date>", {at, body}>`. 오늘 30초, 지난 날 10분. 100개를 넘으면 오래된 것부터 버린다.
- 오늘 화면 1개 기준 1분에 최대 2번 × (runs 1~3 + 자동화 수만큼 Contents) — 토큰 한도(시간당 5000) 대비 여유.

### 4.6 `/api/status` 정리

- `StatusBody.history`, `buildStatus` 의 `todayHistory` 호출을 뺀다. `app/status.ts` 의 `history` 도 뺀다(표 전용 훅으로 옮김).

## 5. 화면

### 5.1 구성

- 제목 "실행 이력"(오늘을 보고 있으면 "오늘 실행 이력"). 오른쪽에 `◀` `날짜 입력(input type=date, min=start, max=today)` `▶` `오늘로`.
- `▶` 는 오늘이면 잠김, `◀` 는 `start` 이면 잠김. 좁은 화면에서는 날짜 줄이 제목 아래로 내려간다.
- 새로 열면 항상 오늘. 날짜는 주소에 남기지 않는다.

### 5.2 표

- 열: 시각 · 자동화 · 방식 · 상태 · **결과** · 소요 · 기록↗.
- 결과: `summary`. 넓이를 넘으면 말줄임, 마우스를 올리면 전체(`title`). 없으면 "–".
- 방식: `manual` 수동, `schedule` 예약, `local` **이 PC**, `other` 기타.
- 기록↗: `url` 이 있을 때만.

### 5.3 데이터 흐름

- 새 훅 `useHistory(ws, date)` (`app/history.ts`): `/api/history` 를 부른다. 오늘이면 30초마다(탭이 보일 때만), 지난 날은 날짜를 바꿀 때 한 번.
- 상태: 불러오는 중 / 빈 날("이 날은 실행한 게 없어요") / `static`("실행 이력은 GitHub 연결이 있을 때만 보여요") / `partial`("GitHub 응답이 없어 일부만 보여요") / 요청 실패("이력을 불러오지 못했어요 · 잠시 뒤 다시 시도").
- 날짜 계산은 순수 함수(`app/history-rules.ts`): `kstToday(now)`, `shiftDate(date, ±1)`, `clampDate(date, start, today)`, `triggerLabel`.
- 가짜 상태 모드(`?mock=…`): 훅이 서버 대신 날짜별 가짜 이력을 만든다. 실행 번호는 자동화·날짜마다 겹치지 않게 만든다(지금 가짜 이력의 key 중복 경고 제거).

## 7. 문서 반영

- `CLAUDE.md` 구조에 `history/`(영구 일지)와 `/api/history` 한 줄.
- 새 자동화는 `report()` 를 쓰는 한 자동으로 일지에 남는다 → 스킬·템플릿 변경 없음.

## 8. 알려진 한계

- 실행이 속하는 날은 GitHub(요청해 만든 날)이 정한다. 실행기가 꺼져 밤새 대기했다가 다음 날 돈 실행도 요청한 날에 한 번만 보이고, 결과 요약·걸린 시간은 일주일 뒤까지의 일지에서 실행 번호로 찾아 붙인다(2026-09-11 실사이트에서 한 실행이 두 날에 보인 것을 발견·수정). 일주일 넘게 대기한 실행, GitHub 이 응답하지 않을 때, 90일이 지난 날에는 일지의 날짜(스크립트 시작 시각)를 따른다.
- 90일이 지난 날의, 결과를 보고하기 전에 끊긴 실행(취소·실행기 없음 등)은 보이지 않는다.

## 9. 범위 밖

- 날짜별 성공/실패 통계, 기간(여러 날) 한꺼번에 보기, 주소에 날짜 저장, 일지 검색.
