# 회의 발언 요약 알림 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 재경위·예결위 생중계 자막을 GitHub 서버에서 받아 위원별로 잘라 Claude 로 요약하고, 10명 묶음(이준석 위원은 단독)으로 530 알림 봇에 보내는 자동화 `speech` 를 만든다.

**Architecture:** 파이썬 `automations/speech/` 가 한 회의 동안 도는 긴 프로세스(자막 수신 → 호명으로 자르기 → 백그라운드 요약 → 묶음 전송, 30초마다 R2 에 상태 저장). Cloudflare Worker 는 구글 캘린더만 보고 회의 시간대에 워크플로를 깨우며(`worker/webcast.ts`), 상태·표시 저장용 작은 API(`worker/speech-state.ts`, R2 `LIVE`)를 둔다. 대시보드는 `assembly` 사무실 `qa` 부서 카드 하나.

**Tech Stack:** Python 3.13(requests, python-socketio<5, websocket-client, pyhwp, bs4/lxml, PyYAML), 공통 모듈 `automations/common/{llm,telegram_bot,report_status}.py`, `automations/mail/mail_gmail.py`; Cloudflare Worker(TypeScript, R2); GitHub Actions(ubuntu). 테스트: pytest, `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-05-회의-발언-요약-알림-design.md`

## Global Constraints

- 공개 저장소: 상태 파일·실행 일지·GitHub Actions 로그에는 **건수와 오류 종류만**. 자막 줄·호명 판정·요약문·위원 이름·일정 제목을 찍지 않는다(설계 10절).
- 비밀값은 `os.environ` 으로만 읽고 코드·문서·커밋에 적지 않는다. 새 비밀값 없음.
- 워크플로에 `schedule:`·`dry_run` 입력을 두지 않는다. 예약·깨우기는 Worker(설계 3·8절).
- 상태 판정 규칙은 `app/status-rules.ts` 에만. 화면 쪽은 값을 넣기만 한다.
- 부서 id 12개 불변. `speech` 는 `dept: "qa"`(현재 `mail` 2명 + 3명 = 5명 ≤ 6).
- 새 파이썬 의존성은 정확히: `python-socketio<5`, `python-engineio<4`, `websocket-client>=1.8`, `pyhwp>=0.1b15` (`automations/requirements.txt`).
- 설정 값(설계 9절): `special_member: "이준석"`, `batch_size: 10`, `segment_max_minutes: 25`, `summary_topics_max: 8`, `notify_target: preview`, `special_member_only_days: true`, 채널 `{ "65": 재경위, "21": 예결위 }`.
- 감시 시간대 = 일정 **시작 10분 전 ~ 끝 3시간 뒤**. 같은 xcode 깨우기 쉬는 시간 **10분**. 텔레그램 한 메시지 **4,096자**.
- 요약 모양·지시문은 설계 6절(사용자 확정). 어미 "~했음", 항목 제목 명사구, `◯` 줄 2~3개, 답변자 "이름 직책".
- 한국어 주석·문구, 번역투 금지. 모듈 이름은 다른 자동화와 겹치지 않게(`speech_*` 접두 불필요하나 `captions.py`·`segmenter.py` 처럼 고유하게).

## Review Focus

1. **동료 언급**("존경하는 이준석 위원님 말씀처럼")은 호명이 아니다 — 새 구간을 열면 안 된다. → Task 4 `test_colleague_mention_is_not_call`.
2. **같은 위원이 두 번 호명**(보충질의) → 두 번째는 새 순번의 새 구간, 앞 구간과 합치지 않는다. → Task 4 `test_second_call_same_member_new_seq`.
3. **재시작 뒤 중복 전송 없음** — 상태의 보낸 순번은 다시 보내지 않고, 열려 있던 구간은 이어 받는다. → Task 6 `test_already_sent_seqs_are_dropped`, Task 8 `test_restore_open_segment`.
4. **위원 한 명이 4,096자를 넘어도** 메시지가 사라지지 않는다(그 위원 안에서 잘라 번호를 붙임). → Task 6 `test_single_member_over_limit_is_hard_split`.
5. **실행이 `queued` 상태**여도 "돌고 있음"으로 봐서 다시 깨우지 않는다; 캘린더 오류·종일 일정은 깨우지 않고 오류만 남긴다. → Task 9 `queued 도 실행 중`, `재경위·예결위 제목만, 종일 일정은 무시`; Task 10 `speechNext: 캘린더 실패면 calendarError 문구`.
