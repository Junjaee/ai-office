# 오피스 실행 구조 재설계 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** "시작" 버튼이 실제 GitHub Actions 자동화를 돌리고, 직원(=하위 작업)의 쉬는 중·일하는 중·끝남·오류만 보이는 단일 페이지 픽셀 오피스로 사이트를 바꾼다.

**Architecture:** 설계 문서 `docs/superpowers/specs/2026-09-10-오피스-실행구조-재설계-design.md`(약 915줄)가 규격의 원천이다. 각본 엔진 `sim.ts`를 버리고 상태→위치·자세 번역기 `engine.ts`를 새로 쓴다. 실행은 Cloudflare Worker `/api/run` → GitHub `workflow_dispatch`, 상태는 `/api/status`(runs API + Contents API) + 정적 폴백. 자동화→하위 작업 매핑의 원천은 `app/workspaces/<id>.ts`.

**Tech Stack:** Next.js(vinext)+React 19, Cloudflare Workers, TypeScript, node --test, Python 3.12/pytest, GitHub Actions(self-hosted runner)

**작업 폴더:** `C:\Users\smart\dev\ai-office` (GitHub Junjaee/ai-office). 명령은 `PATH`에 `C:\Users\smart\AppData\Local\node-x64\node`를 앞에 붙여 실행.

**진행 방식:** 3단계(스키마)를 기존 필드 유지한 채 먼저 넣어 저장소가 계속 컴파일되게 한 뒤, 1단계(파이썬)·2단계(Worker)·상태 규칙을 서로 다른 worktree에서 병렬로 진행하고 main에 합친다. 4단계(엔진·화면)는 그 뒤 한 번에.

- [ ] `report_status.report(...)`: `tasks`, `started_at`, `duration_sec` 인자; `run_id`/`run_url`/`request_id`/`trigger`를 환경변수에서 채움(`GITHUB_RUN_ID`, `GITHUB_SERVER_URL`, `GITHUB_REPOSITORY`, `REQUEST_ID`, `GITHUB_EVENT_NAME`→manual/schedule/local); `running` 항상 False; push 실패 시 `pull --rebase` 후 최대 3회 재시도.
